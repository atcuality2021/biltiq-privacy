## [Unreleased]

- feat: `anonymise()` orchestration + public API — `biltiq_privacy.pipeline.anonymise(text, *, detector, key, generated_at, regime=None, generalise=True, prev_hash=GENESIS_PREV_HASH)` chains Detector → `_merge_detections` (the one ported CDSCO `pipeline.py` algorithm: sort `(start, -score)`, overlap keeps the strictly higher score — intentionally distinct from BILTIQ-015's future cross-backend CompositeDetector) → `Pseudonymiser` → `generalise_text` (opt-out) → `Regime.validate` (opt-in) → `audit_chain.append_row`, returning a frozen `AnonymiseResult` (`anonymised_text`, `detections`, `audit_records`, `audit_row`, `compliance`). Caller supplies `generated_at` + `prev_hash` (no clock read → deterministic, chain-continuable); the chain payload is PII-free (counts, flags, SHA-256 input/output commitments only); empty text still appends a zero-entity attestation row. `biltiq_privacy/__init__.py` now exports the 18-name v0.1.0 public surface with a subprocess-probed lazy-import guarantee (no Presidio/spaCy/FastAPI at import). Packaging made PyPI-publishable (ADR-0006): `en-core-web-sm` moved out of `[project].dependencies` (Warehouse rejects direct-URL `Requires-Dist`) to the dev/CI path; `PresidioDetector` gains opt-in `auto_download_model=False` (default path makes no network call — guard-tested); `MissingNERModelError` names both remedies. 21 new tests (14 facade unit vs a fake detector, 4 public-surface/lazy-import, 3 e2e incl. socket-guard offline run) + 3 detector model-distribution tests; `mypy --strict` clean (BILTIQ-012)
- feat: regime attestation seam + DPDP 2023 validator — `biltiq_privacy.regimes` ships the `Regime` ABC with frozen-dataclass report types (`ComplianceCheck`, `ComplianceReport`, `CheckStatus` four-status `Literal`; `@dataclass(slots=True, frozen=True)` per approved-versions.md — an attestation is not editable after issue) and `DPDPRegime`, porting CDSCO-RegAI's `backend/compliance/dpdp_validator.py` eight checks (`DPDP-1..6`, `NDHM-1`, `ICMR-1`) with IDs, names, descriptions, details and legal-section strings preserved verbatim. `validate(original, anonymised, detections, audit_records, *, generated_at)` consumes the BILTIQ-007 `Detection`/`AuditRecord` TypedDicts (a BILTIQ-009 `DetectedEntity` flows in unchanged) and echoes the caller-supplied timestamp (no clock read → deterministic, the BILTIQ-010 precedent); `compliant` keeps the source's all-pass semantic. The DPDP-1 residual scan reuses BILTIQ-002's eight compiled `PATTERNS` by reference plus a verbatim-ported `EMAIL_PATTERN` (the one pattern 002 lacks) with both token-skip heuristics and the `[:5]` evidence cap preserved. Four dev-ruled behaviour deltas vs the source, each pinned by a named test: stricter 9-type scan; `\b` phone boundary; locators-only evidence by default (`include_values=True` opts into PII-carrying evidence for access-controlled sinks); marker filter wider than the source's `"XXXX"`-only skip — one injected `generalisation_markers` list drives both DPDP-1 filtering and DPDP-4 detection (`("XXXX",)` restores source-strict). Import-light: no Presidio/spaCy/FastAPI load (subprocess probe). 43 tests incl. a detector→pseudonymiser→regime integration round-trip and a recogniser drift guard; manual side-by-side vs the live CDSCO function: 8/8 statuses identical; `mypy --strict` clean (BILTIQ-011)
- feat: age streaming wrapper — `biltiq_privacy.backup.age_stream` (`open_age_writer` / `open_age_reader` context managers around the system `age` binary; `AgeNotInstalledError` / `AgeProcessError` exception hierarchy) + `scripts/install-age.sh` POSIX autodetect installer (Linux / macOS / Windows-shell) + `docs/runbooks/install-age.md` manual-install runbook + ADR-0003 locking the `subprocess.Popen` streaming pattern (BILTIQ-004)
- feat: pure audit hash-chain — `biltiq_privacy.core.audit_chain` ports CDSCO-RegAI's `backend/modules/audit.py` hash-chain core (the ~50-line commitment logic, dropping all SQLAlchemy/persistence coupling) as two stateless free functions plus a genesis sentinel: `append_row(prev_hash, payload)` returns a `ChainedRow` whose `hash` = `hash_text(prev_hash + canonical_json(payload))` (reusing BILTIQ-007's `doc_hasher`, no new SHA-256 path), and `verify_chain(rows)` walks the chain once returning `VerifyReport{valid, first_broken_index}` — recompute mismatch or a broken `prev_hash` link (reorder/insert/delete) is reported, never raised. Timestamps are caller-supplied payload fields (the library never reads the clock → fully deterministic); serialization is canonical JSON (`sort_keys=True`, compact separators, `ensure_ascii=False`) so chains verify byte-identically across machines and languages, with a committed golden vector pinning the cross-language recipe (ADR-0005). `GENESIS_PREV_HASH` is 64 zero hex chars — same width as a real digest, so row 0 needs no special-casing. No DB/SQLAlchemy/FastAPI import; consumers persist rows however they like. Re-exported from `biltiq_privacy.core`. 11 tests (multi-row verify, mutated-payload/mutated-hash/deleted-row tamper detection at the right index, bad-genesis, empty + single-row edges, key-order determinism, golden vector, non-serialisable rejection); `mypy --strict` clean (BILTIQ-010)
- feat: pluggable detection backends — `biltiq_privacy.detectors` now ships the `Detector` ABC + `DetectedEntity` record (`detectors.base`) and the default `PresidioDetector` (`detectors.presidio_backend`) porting CDSCO-RegAI's `detect_pii_rules()` wrapper behind the seam. `PresidioDetector(*, score_threshold=0.5)` reuses BILTIQ-002's `indian.recognisers.build_engine()` (no recogniser re-defined), builds the engine as an instance-level lazy singleton on first `detect()`, projects each Presidio result into a six-key `DetectedEntity` (`source="presidio"`, `round(score,4)`), and filters below the configurable threshold (CDSCO's 0.5 default). `DetectedEntity` extends the 007 `Detection` TypedDict with only `source`, so it flows into the pseudonymiser unchanged — no parallel record type. Presidio/spaCy imports stay method-level and the `AnalyzerEngine` annotation is `TYPE_CHECKING`-guarded, so importing `biltiq_privacy.detectors` loads neither (subprocess probe proves it, AC5); a missing `en_core_web_sm` raises `MissingNERModelError` carrying the `spacy download` hint. 15 tests (3 ABC contract, 2 fixture self-checks, 9 backend behaviour/failure-path, 3 lazy-import) + `MissingNERModelError(RuntimeError)`; `mypy --strict` clean (BILTIQ-009)
- feat: rule-based generaliser — `biltiq_privacy.core.generaliser` ported from CDSCO-RegAI: six field generalisers (`generalise_age` 20-year brackets, `generalise_date` → "Month YYYY" assuming DD/MM ordering, `generalise_location` state→region rollup, `generalise_phone`/`generalise_aadhaar`/`generalise_pan` suffix-masking, each with a `[*_REDACTED]` fallback), plus `generalise_text(pseudonymised_text, spans, *, region_map=None)` routing the 7-key `_GENERALISER` dispatch over `GeneralisationSpan` TypedDict inputs (`entity_type`/`text`/`pseudonym_token`, assembled by BILTIQ-012 from `Detection`+`AuditRecord`). `region_map` is an inject-with-default seam (bundled Indian table; region-pack loader deferred to Phase C). Documented as rule-based generalisation, NOT a dataset-level k-anonymity guarantee (measurement is BILTIQ-021); stdlib + `re` only. 18 tests covering per-function success/fallback, irreversibility, dispatch routing, region_map override, and a source-assertion purity invariant; `mypy --strict` clean (BILTIQ-008)
- feat: core hashing & HMAC pseudonymiser — `biltiq_privacy.core.doc_hasher` (`hash_document`, `hash_text` SHA-256; `hmac_pseudonymise(value, *, key)` HMAC-SHA256 with the key as a keyword-only `bytes | str`, never read from env inside `python-core`), `biltiq_privacy.core.pseudonymiser.Pseudonymiser` (key bound + validated in `__init__`, raising `HMACKeyRequiredError` on an empty key before any text; `make_token(entity_type, value, *, token_length=8)` producing `[TYPE_<hex>]`; `pseudonymise_text` with `Detection`/`AuditRecord` TypedDicts, end→start replacement, restored audit order), and `biltiq_privacy.core.exceptions.HMACKeyRequiredError(ValueError)`; 16 tests covering AC1–AC5 with golden-digest characterization against CDSCO behaviour; added the `hmac_key` test fixture reserved in `stack.md` (BILTIQ-007)
