BILTIQ-007
Author

Created

Approach

Name

Free-function hasher + key-bound Pseudonymiser class, with a dedicated core.exceptions module for HMACKeyRequiredError.

Description

The CDSCO logic is split across two responsibilities, so we port it into two modules that mirror the names already reserved in stack.md and overview.md: core/doc_hasher.py (stateless hashing) and core/pseudonymiser.py (entity → token replacement).

doc_hasher stays a set of pure free functions, matching both the CDSCO original and the signature already advertised in stack.md (hmac_pseudonymise(text, *, key)). The only behavioural change from CDSCO is de-coupling from settings.HMAC_KEY: the key becomes a keyword-only parameter typed bytes | str. A one-line private normaliser utf-8-encodes a str key to bytes (the locked str-convenience decision), so the wire behaviour is byte-identical to CDSCO when the same key text is passed. The two plain SHA-256 functions (hash_document, hash_text) take no key and port verbatim.

pseudonymiser is ported as a Pseudonymiser class (the exact name stack.md reserves) that holds the normalised key on the instance. The key is validated once, in __init__: an empty / missing key raises HMACKeyRequiredError before any text is processed — satisfying AC4 and the overview.md failure-mode contract ("at constructor time, before any text"). make_token(entity_type, value, *, token_length=8) and pseudonymise_text(text, detections) become methods that reuse the instance key, so callers inject the key exactly once rather than threading it through every call. token_length defaults to 8 (CDSCO-equivalent) and slices the hex digest to that width, leaving the [TYPE_<hex>] token form unchanged at the default.

exceptions: HMACKeyRequiredError is named in overview.md but has no home yet. We add core/exceptions.py as the single home for library exceptions (the sibling BiltiqPrivacyImportError / MissingNERModelError named in overview.md will land beside it later). It subclasses ValueError so existing consumers catching value errors are not surprised, while remaining a distinct, catchable type.

Alternatives Considered

#AlternativeWhy Rejected
1Per-call key on the pseudonymiser (key passed to every make_token/pseudonymise_text call)Cannot satisfy AC4's "fail fast at constructor time, before any text is processed"; also re-normalises the key on every call and invites callers to pass inconsistent keys mid-document.
2Module-level singleton key (set once via a module function, read by free functions)Reintroduces exactly the global-state coupling we are porting away from (settings.HMAC_KEY); not safe across multi-tenant keys; violates the "constructor-arg only" rule in overview.md forbidden placements.
3One combined core/pseudonymiser.py holding both hashing and tokenisingHides the stateless SHA-256 helpers (hash_document/hash_text) that audit_chain will want without a key; stack.md already reserves two distinct module names, so merging diverges from the documented surface.
4Raise on missing key only when pseudonymise_text is first called (lazy)Defers the failure past the AC4 boundary ("before any text is processed") and makes the error fire deep in a loop rather than at the injection point; constructor-time validation is cheaper to diagnose.

Data Model Changes

None. No schema, no JSONL field, no SQLite table. The audit list returned by pseudonymise_text is an in-memory list the caller persists (consistent with the library's "no persistence layer" rule in approved-versions.md). Audit-record keys are preserved verbatim from CDSCO: entity_type, pseudonym_token, position_start, position_end, confidence.

API Contract Changes

New public surface under biltiq_privacy.core. No existing contract changes (the modules are new). All signatures are fully typed; no Any, no type: ignore. Detections are typed via a narrow TypedDict rather than bare dict to keep --strict clean while preserving the CDSCO dict shape.

# core/exceptions.py
class HMACKeyRequiredError(ValueError): ...

# core/doc_hasher.py
def hash_document(file_bytes: bytes) -> str: ...
def hash_text(text: str) -> str: ...
def hmac_pseudonymise(value: str, *, key: bytes | str) -> str: ...

# core/pseudonymiser.py
class Detection(TypedDict):
    entity_type: str
    text: str
    start: int
    end: int
    score: float

class AuditRecord(TypedDict):
    entity_type: str
    pseudonym_token: str
    position_start: int
    position_end: int
    confidence: float

class Pseudonymiser:
    def __init__(self, *, key: bytes | str) -> None: ...   # raises HMACKeyRequiredError on empty key
    def make_token(self, entity_type: str, value: str, *, token_length: int = 8) -> str: ...
    def pseudonymise_text(
        self, text: str, detections: list[Detection]
    ) -> tuple[str, list[AuditRecord]]: ...

No new environment variables. No CLI change. The HMAC key never appears as an env read in python-core; it is always a constructor / keyword argument.

Security & Compliance

  • Compliance mode on_prem_preferred: no external / cloud AI calls, no network, no LLM. Pure stdlib hashing. No ADR required — nothing crosses a trust boundary.
  • Key handling — the core compliance point. The HMAC key is never read from env, settings, or any config object inside packages/python-core/. It is a keyword argument only. This is the direct fix for the overview.md forbidden placement "HMAC key reading from env inside packages/python-core/ — constructor-arg only". Env resolution stays in the server tier (Depends() per approved-versions.md), which injects the key into the constructor.
  • Algorithm: HMAC-SHA256 (AC1), unchanged from CDSCO. Plain SHA-256 for document/text fingerprints. No weak digests.
  • Fail-closed on missing key: HMACKeyRequiredError at constructor time prevents any text being tokenised with an absent/empty key (AC4).
  • No secret logging: the key is held on the instance and never logged; tokens are derived one-way and safe to emit. No print(); if logging is added it uses RedactionFilter per stack.md.
  • Pseudonymisation is forward-only by design (spec § Out of Scope) — reversal is the key-holder's concern; no re-identification store is created.

Performance Considerations

Negligible. HMAC-SHA256 over short entity strings and SHA-256 over a document are sub-microsecond to low-microsecond operations; this matches the overview.md budget ("Pseudonymisation + generalisation + audit row: <1 ms"). pseudonymise_text is O(n) in detection count and rebuilds the string from the end backwards (CDSCO algorithm preserved) so offsets stay valid — no quadratic re-scan. Not a hot path relative to Presidio detection (~10–40 ms/KB). No caching needed; the only per-instance setup is one key normalisation.

Risks

RiskSeverityMitigation
Behaviour drift from CDSCO (token format, digest bytes, audit-list keys/order) during the port. MED Characterization tests (AC5) pin the exact token form [TYPE_<hex>], the end-to-start replacement order, the restored audit ordering, and the five audit-record keys against known-fake inputs. Determinism / key-sensitivity test (AC3) locks the digest given a fixed key.
Token collision at the default token_length=8 (32 bits of hex) for very large entity volumes. MED Accepted as CDSCO-equivalent default; token_length is configurable so high-scale consumers widen collision resistance. Document the birthday-bound trade-off in the make_token docstring. A collision vault is out of scope (spec § Out of Scope).
str vs bytes key producing different digests for the "same" key if a caller mixes forms. LOW Locked decision: str is utf-8-encoded internally, so "k" and b"k" yield identical digests. A test asserts str/bytes equivalence to pin this.
HMACKeyRequiredError placement: an inline definition would orphan the future sibling errors named in overview.md. LOW Dedicated core/exceptions.py as the single exception home; subclasses ValueError for backward-friendly catching.

Coordination: core/ is otherwise an empty stub; no other in-flight task touches these files (per MEMORY.md; BILTIQ-006 is in scripts/ memory-spine, disjoint). The new tests/conftest.py + hmac_key fixture is shared scaffolding that BILTIQ-011 / BILTIQ-012 will consume.
