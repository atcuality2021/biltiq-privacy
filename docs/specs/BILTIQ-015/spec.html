Problem

Skyflow's loudest 2026 pitch is GenAI privacy: de-identify before training/RAG/inference, re-identify responses for authorised users, and a "sensitive data dictionary" for business-specific terms. biltiq-privacy already owns every primitive this needs (detect, pseudonymise, generalise, audit, and BILTIQ-014's restore leg) but offers no composed LLM-facing surface — so prospects comparing against Skyflow's demo see a missing product, not present primitives. Their offering also routes data through their SaaS; BiltIQ's own deployment model (vLLM on consumer GPUs) is exactly the customer profile they cannot serve.

User Impact

One import gives a consumer a privacy gate around any OpenAI-compatible client: PII and business-sensitive terms never reach the model; authorised responses are restored in-process; every call is chain-auditable. Works air-gapped. Covers the four GenAI touchpoints (collection, fine-tuning, RAG indexing, inference) as documented recipes over one surface.

Acceptance Criteria

  • OPENAC1 — llm/gate.py ships PrivacyGate(detector, pseudonymiser, *, generalise=False) with protect(text) -> ProtectedText (safe text + session map) and restore(text, session); round-trip preserves non-sensitive content byte-identically and restores sensitive spans only via the session.
  • OPENAC2 — detectors/dictionary.py ships DictionaryDetector(terms, *, normalise=...) behind the BILTIQ-009 Detector ABC: exact + case/whitespace-normalised matching, zero Presidio/spaCy import (subprocess probe), term lists loadable from a consumer file.
  • OPENAC3 — detectors/composite.py merges multiple detectors with deterministic overlap resolution (longest-span-wins, ties by score then detector order); property-tested for span integrity.
  • OPENAC4 — The library makes no network call: the consumer's client object performs the LLM call between protect and restore. Compliance-mode review confirms `on_prem_required` projects can adopt the gate unmodified.
  • OPENAC5 — Per-call audit rows (entities protected, restore events, caller-supplied timestamps) shaped for audit_chain.append_row; chain round-trip test.
  • OPENAC6 — Integration test against a live OpenAI-compatible endpoint (vLLM; CI-skippable env gate) proving protect → chat → restore end-to-end; plus four documented recipes (collection / fine-tuning / RAG / inference) in docs/runbooks/llm-privacy.md.

Out of Scope

  • Bundling any LLM client or model — consumer supplies the client (compliance-mode neutral).
  • MCP exposure of the gate (BILTIQ-025).
  • Streaming-response restoration (follow-up; v1 restores complete responses).
  • Prompt-injection defence — different problem; the gate handles data egress, not jailbreaks. Documented explicitly to avoid overclaiming.

Open Questions

  • Session map: reuse BILTIQ-014's TokenMap (sealed, persistable) or a lighter in-memory dict for the common protect→restore-in-one-process flow? Leaning: in-memory default with optional TokenMap for persistence — design decides.
  • Does protect default to pseudonymise-only, or pseudonymise+generalise? Skyflow defaults to masking; our restore leg argues pseudonymise-only default.
  • Dependency on BILTIQ-014: hard (restore requires it) or soft (restore optional when 014 absent)? Sequencing decision for the sprint plan.
