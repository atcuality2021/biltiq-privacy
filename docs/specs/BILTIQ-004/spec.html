Problem

docs/architecture/stack.md line 52 advertises the age system binary (pinned ≥ 1.2.0) "wrapped via subprocess.Popen for streaming pg_dump | age pipelines" with installation "via scripts/install-age.sh." Neither the Python wrapper module nor the install script exists today. The pre-reserved scaffold at packages/python-core/biltiq_privacy/backup/__init__.py documents the contract ("Backup encryption helpers (age-binary subprocess wrappers, from v0.5.0). Empty marker for the BILTIQ-001 scaffold; modules land in BILTIQ-002+.") but ships empty. Surfaced as tech-debt #1 in the BILTIQ-002 reflect when a user-driven question — "is age enabled on this repo?" — exposed the gap between what stack.md promised and what the codebase actually contained. Until this lands, any consumer code wanting on-prem streaming encryption (the v0.5.0 backup pipeline; future regime-adapter retention enforcement) has no module to import, and operators have no scripted install path.

User Impact

Operational. After this ships:

  • Consumers can from biltiq_privacy.backup.age_stream import open_age_writer, open_age_reader and stream plaintext through age to/from .age files without materialising plaintext on disk — the architectural lever that makes "no plaintext PII on disk" verifiable by a directory-walk regex grep instead of heuristic content inspection.
  • Operators can run bash scripts/install-age.sh on Linux / macOS / Windows-via-package-manager to land age ≥ 1.2.0 on $PATH, with idempotent re-run support and an explicit "needs human" exit code when the script's autodetection falls through.
  • docs/runbooks/install-age.md documents the manual curl-tarball path per OS for users whose package-manager landscape the script doesn't cover.
  • stack.md row at line 52 transitions from forward-looking to shipped — the row's claim now matches the repo state, closing the BILTIQ-002 reflect tech-debt entry that triggered this ticket.

Acceptance Criteria

  • OPEN AC1 — Module biltiq_privacy.backup.age_stream exists and exports two context managers: open_age_writer(out_path: Path, *, recipient: str) -> Iterator[IO[bytes]] and open_age_reader(in_path: Path, *, identity_path: Path) -> Iterator[IO[bytes]]. Both raise AgeNotInstalledError (subclass of FileNotFoundError) at __enter__ if shutil.which("age") returns None.
  • OPEN AC2 — open_age_writer streams bytes through subprocess.Popen(["age", "-r", recipient, "-o", str(out_path)], stdin=PIPE). The yielded handle is the subprocess stdin; plaintext is written to it; ciphertext lands at out_path. No NamedTemporaryFile, no buffer-to-disk; the plaintext exists only in pipe buffers and process memory.
  • OPEN AC3 — open_age_reader streams ciphertext through subprocess.Popen(["age", "-d", "-i", str(identity_path), str(in_path)], stdout=PIPE). The yielded handle is the subprocess stdout; reading from it returns decrypted plaintext. Symmetric with AC2 — no plaintext on disk.
  • OPEN AC4 — Both context managers raise AgeProcessError (subclass of subprocess.CalledProcessError) on non-zero exit at __exit__. stderr is captured and surfaced in exc.stderr as bytes. No silent failures, no bare except: (Anti-Pattern #3 defence).
  • OPEN AC5 — Round-trip test: a test generates an ephemeral keypair via age-keygen in tmp_path, writes a synthetic plaintext byte string through open_age_writer, reads it back through open_age_reader, asserts plaintext_in == plaintext_out. Keys never committed. Synthetic data only (no real PII).
  • OPEN AC6 — Test suite gates on age presence via pytest.mark.skipif(not shutil.which("age"), reason="age binary not on PATH"), matching the CDSCO-RegAI test_backup_pg_surface.py:27 pattern. A positive-control test asserts the skip mechanism itself runs (i.e. the suite is not silently empty when age is present).
  • OPEN AC7 — scripts/install-age.sh (POSIX sh) installs age ≥ 1.2.0 with this autodetect order: (a) Linux — apt-get → dnf → pacman → snap → GitHub-release tarball + SHA256 verify; (b) macOS — Homebrew if present → GitHub-release tarball + SHA256 verify; (c) Windows under MSYS2/Cygwin/MinGW — print directive to install via scoop install age or choco install age and exit 2 (distinguishable from script-broken exit 1). Idempotent — refuses to overwrite an existing age ≥ 1.2.0 on $PATH unless --force. Flags: --force, --uninstall (removes only what the script installed; refuses to remove a system-package-managed binary), -h/--help. Style mirrors scripts/install-curator-hook.sh.
  • OPEN AC8 — docs/runbooks/install-age.md documents the manual curl-tarball install per OS (Linux x86_64, Linux arm64, macOS Intel + Apple Silicon, Windows scoop/choco). Includes the upstream GitHub release URL pattern, the SHA256 verification command, the $PATH placement step, and a verification command (age --version). For users whose package-manager landscape the autodetect script doesn't cover.
  • OPEN AC9 — Three architecture doc files updated in the same PR: (a) docs/architecture/stack.md line 52 row replaces forward-looking "Install via scripts/install-age.sh" phrasing with a shipped-row layout referencing the wrapper module path + the install script + the runbook + ADR-0003; § Internal modules adds a row for biltiq_privacy.backup.age_stream. (b) docs/architecture/overview.md line 43 replaces forward-looking backup/{age_pipeline,manifest}.py with the actual backup/age_stream.py + note that the orchestrator modules land in BILTIQ-005+; line 156 renames the anticipated AgeBinaryNotFoundError to the spec-locked AgeNotInstalledError. (c) docs/architecture/approved-versions.md § Currently approved adds a one-row entry "age ≥ 1.2.0 (system binary; pinned in stack.md + scripts/install-age.sh)" so anti-pattern #9 (deprecated APIs) defence covers age alongside Python / Presidio / spaCy.
  • OPEN AC10 — Static-grep meta-test packages/python-core/tests/backup/test_no_intermediate_files.py opens age_stream.py as text and asserts no occurrences of NamedTemporaryFile, tempfile.mkstemp, tempfile.NamedTemporary, Path.write_bytes, or .write_text( in the module source. Lifts the AC2/AC3 "no plaintext on disk" invariant from a code-review-only check (Risk #3) to an in-CI gate. Runs unconditionally — no skipif(not shutil.which("age")) needed since the test reads source text, not the binary.

Out of Scope

  • Backup orchestrator (Postgres pg_dump pipeline, Qdrant snapshots, uploads tar bundles, HMAC-signed MANIFEST.json) — deferred to BILTIQ-005+. The wrapper is the primitive; the orchestrator that calls it ships separately.
  • Per-appliance keypair generation + storage convention (the CDSCO-RegAI config/age-recipients/<APPLIANCE_ID>/ layout) — deferred. Callers of open_age_writer supply the recipient public key string; how they obtain or store it is not this ticket's concern.
  • Key rotation policy + tooling — deferred to v0.5.0 when the orchestrator lands.
  • Format compatibility with CDSCO-RegAI backup bundles — we handle bare .age files in both directions, but we do not promise to read CDSCO-RegAI's manifest-bundled archives. That's an orchestrator concern.
  • Native PowerShell .ps1 installer for Windows — Windows path is "run from MSYS2/Cygwin/MinGW shell" or follow the manual-install runbook. A native .ps1 sibling is a follow-up ticket if Windows-native operator demand materialises.
  • Async / asyncio variant of the context managers — sync subprocess.Popen only. The library convention from approved-versions.md allows async timeouts but the streaming pattern is naturally sync; async adapter is a follow-up if a consumer needs it.
  • Vendoring or forking age — we depend on the system binary, never vendor or fork it. Same rule that applies to Presidio (Brief §2 rule 1).
