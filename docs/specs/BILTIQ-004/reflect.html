What Went Well

  • Parallel 4-slice code review on the 19-file diff (Step 4) caught what inline review would have rolled past. Slice D found two doc-drift issues (ADR-0003 stating "9 ACs" when spec.html had grown to 10; plan.html missing a Change-History row for the plan-reviewer verdict). Both were 1-line fixes but real audit-trail gaps. The dispatch cost (4 subagents) was justified by the file count crossing the ≥ 10 trigger threshold.
  • AC10 static-source-grep meta-test is a category of test we should reach for more often. The 5-parametrize test in test_no_intermediate_files.py greps the wrapper’s own source for forbidden patterns (NamedTemporaryFile, tempfile.mkstemp, Path.write_bytes, etc.). It catches a class of regression (future contributor adds a tempfile shortcut) that no behavioral test can see at runtime. Worth proposing as a pattern for other security-invariant modules.
  • ADR-0003 written at Step 1 / locked at Step 6 prevented Build-phase second-guessing. The four-alternatives-rejected encryption-backend decision and two-alternatives-rejected exception-hierarchy decision were settled in design.html + ADR-0003 before any wrapper code was written. Build phase had no “should we switch to pyca/cryptography instead?” detours.
  • Plan-reviewer’s compose-vs-spec heuristic was pre-empted at draft time, not surfaced at review time. plan.html’s per-step compose summed to ~375 min (L band) vs spec.html’s original M band. The 2026-05-18 spec amendment widened Wall-clock M → L pre-emptively so plan-reviewer didn’t fire a “single-step-too-large” warning. Lesson: when plan-step compose lands in a higher band than spec, amend the spec at plan-draft time, not at review time.
  • Step 7 install-age.sh shipped shellcheck-clean. One printf-format fix mid-dev was the only correction needed before commit. The POSIX-compliance discipline (no bashisms, every-branch-fallback, SHA256-pinned) paid for itself.
