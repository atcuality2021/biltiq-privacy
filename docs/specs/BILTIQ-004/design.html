Approach

Name

Two streaming subprocess.Popen context managers under biltiq_privacy.backup.age_stream, plus a POSIX-sh autodetect installer and a manual-install runbook — ported in pattern from CDSCO-RegAI's scripts/_backup_lib/age_stream.py, re-derived for the library audience.

Description

The spec locks five invariants: (1) module path biltiq_privacy.backup.age_stream; (2) two context managers (open_age_writer, open_age_reader) whose yielded handle is the subprocess pipe end — never a temporary plaintext file; (3) two exception classes (AgeNotInstalledError as a FileNotFoundError subclass; AgeProcessError as a subprocess.CalledProcessError subclass) raised at well-defined lifecycle points; (4) a cross-OS install script with a fixed autodetect order and an explicit "needs human" exit code; (5) a manual-install runbook covering OSes the script does not autodetect. Those five together force the topology below.

Both context managers wrap a single subprocess.Popen(["age", ...], stdin=PIPE, stdout=...) call. The writer's yielded handle is proc.stdin (caller writes plaintext bytes; ciphertext lands at out_path via age's -o flag). The reader's yielded handle is proc.stdout (caller reads decrypted plaintext bytes; ciphertext is piped in via proc.stdin from a file handle opened on in_path). Neither path materialises plaintext on disk — the AC2/AC3 invariant. shutil.which("age") is checked at __enter__; absence raises AgeNotInstalledError. At __exit__ the subprocess is waited on under a try/finally that always closes stdin/stdout/stderr; non-zero exit raises AgeProcessError with stderr bytes captured. Exception propagation from the caller's with body (e.g. the consumer's writer raises mid-stream) tears the subprocess down cleanly via a BaseException handler that closes stdin, waits the process, and unlinks any partial ciphertext file before re-raising — this is the same pattern CDSCO-RegAI's _backup_lib/age_stream.py uses, re-derived for our exception hierarchy.

The install script (scripts/install-age.sh) is POSIX-sh, mirroring the style of scripts/install-curator-hook.sh (BILTIQ-003): set -u; explicit arg parser; -h/--help emits a slice of its own header; idempotent install with --force override; safe --uninstall that refuses to remove anything it did not place. Autodetect order is fixed per AC7: Linux package managers (apt-get → dnf → pacman → snap) → GitHub-release tarball with SHA256 verify; macOS Homebrew → GitHub-release tarball with SHA256 verify; Windows shells (MSYS2 / Cygwin / MinGW) → emit a directive to use scoop or choco and exit 2 (distinct from "script broken" exit 1). The runbook (docs/runbooks/install-age.md) covers manual curl-based installs per (OS × arch) for the path the script does not autodetect — the GitHub-release URL pattern, the SHA256 check, the $PATH placement step, and a final age --version verification.

The trade-off accepted: the wrapper is a thin shell around subprocess.Popen; it adds error typing, lifecycle hygiene, and a shutil.which gate, but does not abstract age itself (no recipient-file resolution, no key generation, no manifest, no SHA256 of the ciphertext — those concerns live in the future v0.5.0 backup orchestrator per spec § Out of Scope §1, §2, §3). This deliberately keeps the surface stateless / IO-only: the recipient is a caller-supplied string; the identity path is a caller-supplied Path; nothing about keys, key custody, or recipient-file layout is the wrapper's business. Consumers wire those concerns themselves in BILTIQ-005+, which is when the CDSCO-RegAI config/age-recipients/<APPLIANCE_ID>/ convention may be ported (or not) to this codebase.

Install-script strategy (chosen: POSIX-sh autodetect + GitHub-release fallback)

Exception hierarchy shape (chosen: subclasses of stdlib base classes)

#AlternativeWhy Rejected / Chosen
1Library-internal base class (e.g. BackupError / RestoreError) like CDSCO-RegAI's scripts/_backup_lib/errors.py shape.Rejected. CDSCO-RegAI was an application; biltiq-privacy is a library. Library callers want to except FileNotFoundError (for missing binary) and except subprocess.CalledProcessError (for non-zero exit) without importing our private exception class. Subclassing the stdlib bases gives callers both surfaces without forcing an import.
2Single AgeError class for both failure modes.Rejected. Conflates two operationally-different conditions: "age isn't installed" (the operator needs to run the install script) versus "age exited non-zero" (a recipient / identity / ciphertext-corruption problem). Spec AC1 and AC4 keep them separate; the design preserves that.
3 ✓AgeNotInstalledError(FileNotFoundError) raised at __enter__ when shutil.which("age") is None; AgeProcessError(subprocess.CalledProcessError) raised at __exit__ on non-zero exit, with stderr bytes carried through exc.stderr (chosen).Direct match to AC1 + AC4. Callers can except FileNotFoundError for the install gate (a familiar idiom for missing-binary checks) and except subprocess.CalledProcessError for the runtime gate (stdlib semantics, including .returncode and .stderr attributes). No new import burden on consumers who want broad handling; narrow handling via the typed subclasses works when callers want it.

Data Model Changes

None. The wrapper is stateless and IO-only. No schemas, no JSONL fields, no SQLite tables, no audit-chain row changes, no in-process caches, no module-global state. open_age_writer and open_age_reader are @contextmanager-decorated generator functions; each invocation owns its own subprocess and its own pipe-buffer state and tears both down at __exit__. Recipients and identities are caller-supplied at call time and are not persisted by the wrapper.

API Contract Changes

Four new public Python symbols ship under biltiq_privacy.backup (additive; the sub-package was a scaffold-empty marker in BILTIQ-001 with the docstring contract this ticket satisfies):

# biltiq_privacy.backup.age_stream

class AgeNotInstalledError(FileNotFoundError):
    """Raised at __enter__ when shutil.which("age") returns None.
    Subclasses FileNotFoundError so callers can `except FileNotFoundError`
    without importing this module's private exceptions."""

class AgeProcessError(subprocess.CalledProcessError):
    """Raised at __exit__ when the age subprocess exits non-zero.
    Inherits .returncode, .cmd, .stderr (bytes) from the stdlib base.
    No bare `except:` paths in the wrapper (AGENT_RULES.md anti-pattern #3)."""

@contextmanager
def open_age_writer(
    out_path: Path,
    *,
    recipient: str,
) -> Iterator[IO[bytes]]:
    """Stream plaintext bytes through `age -r <recipient> -o <out_path>`.

    Yields the subprocess stdin handle. Bytes written are encrypted
    and land at `out_path`. Plaintext exists only in pipe buffers
    and process memory — never on disk.

    Raises:
      AgeNotInstalledError: at __enter__ if `age` is not on $PATH.
      AgeProcessError:      at __exit__ if `age` exits non-zero.
    """

@contextmanager
def open_age_reader(
    in_path: Path,
    *,
    identity_path: Path,
) -> Iterator[IO[bytes]]:
    """Stream ciphertext from `in_path` through `age -d -i <identity_path>`.

    Yields the subprocess stdout handle. Reading from it returns
    decrypted plaintext bytes. Symmetric with open_age_writer:
    no plaintext on disk.

    Raises:
      AgeNotInstalledError: at __enter__ if `age` is not on $PATH.
      AgeProcessError:      at __exit__ if `age` exits non-zero.
    """

Import path contract: the four symbols are re-exported from biltiq_privacy.backup via the sub-package __init__.py. Callers may write from biltiq_privacy.backup import open_age_writer, AgeNotInstalledError; the leaf-module path from biltiq_privacy.backup.age_stream import ... remains valid (and is what AC1 names literally). biltiq_privacy/__init__.py stays empty of these symbols — consistent with the BILTIQ-002 sub-module-only import-path lock.

CLI contract (scripts/install-age.sh): three flags (--force, --uninstall, -h/--help) and three exit codes (0 success / 1 script broken / 2 needs human). Stable for the life of the script; downstream automation may key off the exit-code distinction.

Security & Compliance

  • Compliance mode: on_prem_preferred. This task introduces zero external AI / cloud API calls. The wrapper runs the local system age binary via subprocess.Popen; no HTTP client, no environment-variable reads inside packages/python-core/, no DNS lookups, no key material leaving the calling process. The on-prem-compliance gate (AGENT_RULES.md § Compliance mode) does not fire — no ADR-for-external-AI required.
  • Trust model for the age binary. The wrapper executes whatever age binary is on the caller's $PATH. We trust the OS package manager that installed age (apt / dnf / pacman / snap / Homebrew / scoop / choco) to deliver an authentic binary. The single place this ticket touches that trust boundary directly is in scripts/install-age.sh's GitHub-release tarball fallback path, which fetches the tarball + a SHA256 file from the FiloSottile/age release URL and verifies the checksum before placing the binary on $PATH. The SHA256 baseline for the pinned AGE_VERSION is committed in-script — tampering with the upstream release page alone is not sufficient to compromise the installer; the attacker would also need a matching SHA256 commit to the repo (visible in git blame). For package-manager paths, trust is delegated to the upstream package signing chain (apt / dnf / pacman / brew / snap / scoop / choco all sign their packages by default on modern installs); the install script does not re-verify what the package manager has already verified.
  • Key material. The wrapper never persists, copies, or logs key material. Recipients (public keys) are passed as opaque strings (recipient: str); identities (private keys) are passed as Path objects and forwarded to age -i <path> verbatim. The wrapper never opens an identity file in Python — age handles that. Callers (BILTIQ-005+ backup orchestrator) own key custody; this ticket adds no opinion.
  • No plaintext on disk — the AC2/AC3 invariant. Provable only by code review of the implementation, not by a runtime test (a test that asserts "no plaintext appeared in /tmp during the writer's lifetime" would race the writer's own pipe activity). Mitigation: the implementation in age_stream.py is small (under 100 LOC); the code-reviewer skill check at Step 4 verifies the absence of NamedTemporaryFile, tempfile.mkstemp, Path.write_bytes against plaintext, or any intermediate-file pattern. Recorded as Risk #3 below.
  • No PII in logs. The wrapper does not log input bytes (those are PII when the consumer is the backup orchestrator). If diagnostic logging is added later, it routes through biltiq_privacy.core.log_filter.RedactionFilter (stack.md). For BILTIQ-004, the module emits no log records — pure data + pure functions modulo the subprocess effect.
  • No secrets. No HMAC keys, no API tokens, no env reads inside packages/python-core/. The install script reads no secrets either; the only environment variables it touches are $PATH (read-only) and $HOME (for the $HOME/.local/bin/ tarball-install fallback).
  • Subprocess invocation hygiene. Every subprocess.Popen call passes an argv list, never shell=True. Caller-supplied values (recipient as str, paths as Path) are passed as separate argv elements; the shell never interpolates them. Removes the shell-injection class of bugs by construction.
  • Library/server boundary. packages/python-core/ only — no FastAPI / Starlette / uvicorn imports. scripts/check-boundaries.sh (BILTIQ-001) catches any accident in CI.
  • License hygiene. SPDX header on every new .py file. age itself is BSD-3-Clause licensed (upstream); we depend on the binary at runtime, do not vendor, do not link. Per approved-versions.md: no GPL / AGPL contamination risk in this change.
  • No ADR required for an external AI dependency (none introduced). ADR-0003 is written to lock the subprocess.Popen streaming pattern itself — an architectural-decision ADR, not a compliance-override ADR.

Performance Considerations

  • Pipe-buffer throughput. The Linux default pipe buffer is 64 KiB (16 × 4 KiB pages; PIPE_BUF is the smaller atomic-write threshold). The wrapper does no buffering of its own; the caller writes directly to proc.stdin in whatever chunk size it chooses, and age reads from its stdin via its own internal loop. Per CDSCO-RegAI's 50 MiB streaming round-trip test (test_age_stream_round_trip_50mb_streaming), throughput is comfortably above 1 MB/s on commodity hardware — the bottleneck is ChaCha20-Poly1305 inside age, not Python or the pipe.
  • GIL. The encrypt / decrypt work happens in the age subprocess, not in the calling Python process. The Python wrapper only serialises writes to proc.stdin (and reads from proc.stdout in the reader path). No GIL contention introduced; consumers can use the wrapper from a thread without blocking other threads on encryption work.
  • Subprocess startup cost. One fork+exec per open_age_* invocation. On Linux that is sub-millisecond; on macOS it is in the low milliseconds. Negligible against any real-world plaintext volume. For the BILTIQ-005+ backup orchestrator's typical envelope (one age subprocess per surface — Postgres dump, Qdrant snapshot, uploads tar, config bundle, i.e. ~4 subprocesses per backup run), the aggregate cost is well under 100 ms of process-start overhead.
  • Import cost. from biltiq_privacy.backup.age_stream import open_age_writer pulls only stdlib (shutil, subprocess, contextlib, pathlib, typing). Cost is dominated by Python bytecode load — sub-millisecond. No Presidio / spaCy bleed-in (those live under biltiq_privacy.indian.*, an unrelated sub-package).
  • Test-suite cost. 6 tests in test_age_stream.py: the round-trip test runs age twice per invocation (encrypt + decrypt) for ~50 ms × 2 = ~100 ms; error-path tests run age once each. Whole test module under 1 s wall-clock; comfortably inside CI budget. The age_test_keypair fixture spawns age-keygen once per test (cheap; sub-100 ms); a module-scoped fixture would halve this but the spec does not require optimisation.

Pure additive Python code under an existing scaffolded sub-package, plus one shell script, one runbook, one ADR, three documentation edits, and one CHANGELOG entry. Risks

#RiskSeverityDetection / Mitigation
1 Install-script paths only locally validated on Linux. AC7 mandates code paths for Linux (apt / dnf / pacman / snap / GitHub-release fallback), macOS (Homebrew / GitHub-release fallback), and Windows shells (scoop / choco directive + exit 2). The dev's primary environment is Linux; GitHub-hosted CI runners exercise the Linux + macOS paths but not the Windows-shell branches. The Windows-shell branch is coded but not autoexecuted by CI — meaning the directive-and-exit-2 behaviour is correct-by-inspection, not correct-by-test. MEDIUM Detection: shellcheck in CI catches syntax / quoting bugs on all branches regardless of which OS runs. bash scripts/install-age.sh --help smoke runs on the Linux CI cell. Mitigation: at Step 5 (Test), the dev manually runs the macOS Homebrew path on a personal macOS device (or skips with a documented gap), and the Windows-shell branch is tested manually under MSYS2 (or skipped with a gap). Gaps land in the Step 6 (Ship) PR description's "known unvalidated paths" section so reviewers see what is and isn't proven. This pattern matches BILTIQ-002's CI-vs-platform-coverage gap honesty.
2 Popen cleanup on exception requires careful context-manager finalisation. The @contextmanager function must close proc.stdin, drain proc.stdout / proc.stderr, and wait on the subprocess on every exit path — including when the caller's with body raises mid-stream. A bug here yields orphaned age subprocesses on disk (process table leak) and possibly a partial ciphertext file at out_path. CDSCO-RegAI's age_stream.py handles this via an explicit except BaseException: proc.stdin.close(); proc.wait(); path.exists() and path.unlink(); raise block; this design ports the same pattern. MEDIUM Detection: a dedicated test ("writer body raises mid-stream") that opens the writer, writes some bytes, then raises a custom exception inside the with block; asserts (a) the custom exception propagates, (b) no orphan age process remains (proc.poll() returns a value), (c) the partial out_path is unlinked. AC4 only covers the non-zero-exit case; this risk's mitigation is one test beyond what AC4 explicitly demands. Mitigation: ports CDSCO-RegAI's exception-clean shape verbatim modulo the new exception class names. Code reviewer to verify the try/except BaseException/finally shape mirrors the source.
3 AC2 / AC3 "no plaintext on disk" — code-review invariant lifted to in-CI gate at design review. Originally MEDIUM: a runtime test that asserts "no plaintext appeared in /tmp during the writer's lifetime" would race the writer's own pipe activity and would not reliably catch a regression. At design review (dev decision Q2), AC10 was added to the spec: a static-grep meta-test (tests/backup/test_no_intermediate_files.py) opens age_stream.py as text and asserts no occurrences of NamedTemporaryFile, tempfile.mkstemp, Path.write_bytes, etc. The invariant is now a CI gate, not a code-review-only check. LOW Detection: AC10's static-grep test fails the build if any forbidden pattern appears in age_stream.py. Additional defence: code-reviewer skill check at Step 4 explicitly looks for the same patterns; module docstring carries an explicit "DO NOT introduce intermediate plaintext files; AC2/AC3 invariant" warning. Three independent gates (CI test, skill check, in-source comment).
4 SHA256 baseline maintenance. scripts/install-age.sh hard-codes a pinned AGE_VERSION and the SHA256 baseline for each (OS × arch) tarball. When age publishes a new version (1.2.x → 1.3.x), the baseline goes stale — the GitHub-release fallback either downloads a still-valid pinned version (OK, install succeeds at the pinned version) or, if FiloSottile rotates artifacts (rare but allowed), starts failing the SHA256 check. The install script's correctness is now coupled to upstream release-pin policy. LOW Detection: a follow-up maintenance check ("does age --version on a fresh-install Linux runner still report ≥ 1.2.0?") could be CI-scheduled, but out of scope for BILTIQ-004. Mitigation: the script's behaviour on SHA256-mismatch is to exit 1 with a clear message ("expected SHA256 X, got Y; refusing to install"), pointing the operator at docs/runbooks/install-age.md for the manual path. Operators are never silently exposed to a tampered tarball.
5 Doc drift between overview.md and the chosen module name. docs/architecture/overview.md line 43 anticipated backup/{age_pipeline,manifest}.py (forward-looking from BILTIQ-001) and line 156 anticipated AgeBinaryNotFoundError. Neither matches the spec-locked names (backup/age_stream.py and AgeNotInstalledError). If the overview.md edit is skipped, future devs onboarding from overview.md will look in the wrong place / for the wrong exception — Anti-Pattern #1. LOW Detection: code-reviewer skill flags any new internal module not registered in stack.md § Internal modules. Mitigation: documentation deltas are explicit in § Files to Touch — both stack.md and overview.md edits land in the same PR. plan.html will include the doc-update commit before the ADR commit. This pattern mirrors BILTIQ-002's overview.md drift fix.
6 age version pin in approved-versions.md — closed at design review. Originally LOW: approved-versions.md did not carry a row for the age binary, so the two pin locations (stack.md line 52 + the install script's AGE_VERSION) could drift without anti-pattern #9 defence catching it. At design review (dev decision Q1), AC9 was expanded to include approved-versions.md; the file now lands a one-row entry "age ≥ 1.2.0 (system binary; pinned in stack.md + scripts/install-age.sh)". Three pin locations all in sync via the same PR. MITIGATED Detection: code-reviewer skill checks for new external version pins; with approved-versions.md carrying the row, any drift in stack.md or the install script's AGE_VERSION shows up as an inconsistency the reviewer can flag. Future bumps (1.2.0 → 1.3.0) update all three locations in the same PR.

Anti-Pattern Guardrails Honored

  • #1 Duplication — the BILTIQ-001 scaffold pre-reserved packages/python-core/biltiq_privacy/backup/__init__.py with the exact docstring contract this ticket satisfies. We use the scaffold rather than creating a new sub-package, and we update its docstring to mark the BILTIQ-004 close-out. The wrapper does not reimplement what biltiq_privacy.core.log_filter.RedactionFilter or any existing utility already does — there is no overlap between subprocess streaming and the existing internal modules.
  • #2 Abstraction Bypass — we invoke subprocess.Popen directly (no hand-rolled subprocess abstraction in the repo today); we use shutil.which, pathlib.Path, and contextlib.contextmanager per stack.md § Shared utilities. No hand-rolled os.path reimplementation and no shell-string interpolation.
  • #3 Error Handling Gaps — open_age_writer and open_age_reader handle the four error modes explicitly: (a) binary absent → AgeNotInstalledError at __enter__, (b) non-zero exit → AgeProcessError at __exit__ with stderr captured, (c) body raises mid-stream → cleanup via except BaseException + unlink-partial-file + re-raise, (d) caller closes the pipe early → handled by proc.wait() seeing EOF on stdin. No bare except:; no except Exception: pass swallow.
  • #4 Type Safety Violations — recipient: str, identity_path: Path, out_path: Path, in_path: Path, return type Iterator[IO[bytes]] on both context managers. AgeNotInstalledError and AgeProcessError typed against their stdlib bases. No Any; no # type: ignore planned (the wrapper has no third-party imports, so there's no missing-stubs gap).
  • #5 Security Anti-Patterns — no SQL; subprocess.Popen is invoked with an argv list (never shell=True) so caller-supplied recipient and identity_path are never shell-interpolated; no secrets read or logged; the install script's GitHub-release tarball path verifies SHA256 against a committed-in-script baseline before placing the downloaded binary on $PATH. Trust boundary documented under § Security & Compliance.
  • #6 Dead Code / Over-engineering — two context managers, two exception classes, one private _check_age_binary helper. No speculative key-rotation hooks, no recipient-resolution machinery, no manifest interfaces (those are the v0.5.0+ orchestrator's job, explicitly carved out by spec § Out of Scope §1, §2, §3, §4).
  • #7 Debugging Residue — no *_v2.py, *_new.py, *_old.py, *.bak, test_scratch_*.py, no commented-out code. biltiq-gates.yml residue check covers this.
  • #8 Async Misuse — spec § Out of Scope §6 carves async out. Both context managers are sync; no asyncio imports.
  • #9 Deprecated API Usage — shutil.which, subprocess.Popen, contextlib.contextmanager, pathlib.Path, typing.IO, collections.abc.Iterator: all current per approved-versions.md. from __future__ import annotations at the top of every new .py file. No datetime.utcnow, no os.path, no print(), no bare except:.
  • #10 Fake Test Coverage — each test in test_age_stream.py asserts one behaviour tied to one AC (or one risk-mitigation contract). Round-trip test asserts byte equality, not just "didn't crash". Error-path tests assert the exception type AND the captured stderr (isinstance(exc, subprocess.CalledProcessError) AND exc.stderr is not None).
  • #11 HTML/MD boundary — clean. This file is design.html; the runbook is docs/runbooks/install-age.md (operator-facing playbook, MD permitted — not in the spec/design/plan/reflect set that triggers the HTML rule); the ADR is docs/adr/0003-age-streaming-pattern.md (ADRs remain MD per the precedent of ADR-0001 and ADR-0002).
