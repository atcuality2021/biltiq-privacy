Problem

BILTIQ-007–011 deliver the pipeline pieces; nothing yet ties them together or presents a public entry point. CDSCO's pipeline.py orchestrates detect→merge→pseudonymise→generalise but is coupled to a PDF extractor and an optional LLM call. This task ports the orchestration as a clean library function over text input (extraction is the caller's concern), wires the public biltiq_privacy API, and tags the first publishable release v0.1.0.

User Impact

External. First usable release: pip install biltiq-privacy, then anonymise(text, detector=..., key=..., regime=...) returns anonymised text + detections + audit row + compliance report. This is the milestone where the library becomes consumable by CDSCO, CommandCenter, and ManthanQuant.

Acceptance Criteria

  • OPENAC1 — A top-level anonymise(text, *, detector, key, regime=None, generalise=True) -> AnonymiseResult chains Detector→Pseudonymiser→Generaliser→(Regime)→AuditChain; result carries anonymised_text, detections, audit_row, and compliance (when a regime is given).
  • OPENAC2 — biltiq_privacy/__init__.py exports the public surface (anonymise, PresidioDetector, Detector, Regime, DPDPRegime, error types) with a stable, documented API.
  • OPENAC3 — End-to-end integration test: raw text containing Indian PII → detected → pseudonymised → generalised → DPDP report passes → audit row verifies.
  • OPENAC4 — Default path imports no PDF/LLM/DB/FastAPI; LLM detection is opt-in only via an injected detector (Phase D). Compliance: on_prem_preferred respected.
  • OPENAC5 — Package version set to 0.1.0; CHANGELOG.md entry added; README has a runnable usage example.
  • OPENAC6 — python-core builds and imports cleanly; full test suite green; passes --strict type check + banned-vocab/residue gates.

Out of Scope

  • REST sidecar (BILTIQ-013) and native SDKs (Phase E).
  • PDF/CSV extraction adapters — caller passes text (may be a thin follow-up helper).
  • LLM/hybrid detection (Phase D); extra regimes/region packs (Phase C).

Open Questions

  • Result type — dataclass vs TypedDict? Lean dataclass for the public API.
  • Should anonymise() require a regime, or make compliance opt-in? Lean opt-in (detection+pseudonymise+generalise is useful alone).
  • Publish to PyPI as part of this task, or tag-only and publish in a separate release task? Confirm.
