Approach

Name

Thin facade module (pipeline.py) over existing wrappers, eagerly re-exported from __init__.py — composition only, one ported helper.

Description

A new module biltiq_privacy/pipeline.py holds the frozen AnonymiseResult dataclass, the private _merge_detections helper (the only logic ported from CDSCO pipeline.py — sort by (start, -score), overlapping span keeps the higher score), and the public anonymise() function that chains the five already-shipped pieces: Detector.detect → _merge_detections → Pseudonymiser.pseudonymise_text → generalise_text (opt-out) → Regime.validate (opt-in) → audit_chain.append_row. The facade contributes no new algorithms beyond merge-dedup, the GeneralisationSpan zip assembly that core/generaliser.py:157 explicitly assigns to this task, and the audit-payload dict (counts and hashes only — no PII). __init__.py re-exports the public surface with plain eager imports: this is verified safe because every heavy import in the chain is already method-level (presidio_backend.detect() defers Presidio/spaCy; regimes and core are stdlib-light), so import biltiq_privacy stays lazy without any __getattr__ machinery — pinned by a new subprocess probe mirroring tests/detectors/test_lazy_import.py. The library reads no clock and no environment: generated_at is a required caller-supplied kwarg and prev_hash defaults to GENESIS_PREV_HASH (dev-ruled 2026-06-11; BILTIQ-010/011 determinism precedent), so identical inputs always produce an ==-comparable result.

Pipeline ordering invariant (load-bearing, test-pinned)

_merge_detections emits detections in start order and non-overlapping; pseudonymise_text replaces end-of-string-backwards and then reverses its audit list back to document order — therefore zip(detections, audit_records) aligns one-to-one, and that zip builds the GeneralisationSpan list (entity_type + text from the detection, pseudonym_token from the audit record). A dedicated test feeds deliberately out-of-order detector output to pin this alignment.

Empty-text / zero-detection behaviour (decided)

CDSCO early-returns an empty dict before detection. The facade instead keeps one uniform path: only the detector.detect() call is skipped when text.strip() is empty (avoids a pointless spaCy model load); pseudonymise/generalise are no-ops over an empty detection list; the regime (if given) still validates; and the audit row is always appended, recording a zero-entity run. Rationale: "nothing found" is itself a compliance-relevant attestation — an auditor must be able to distinguish "document processed, no PII detected" from "document never processed". Key validation still fails fast (the Pseudonymiser is constructed first), so an empty key raises HMACKeyRequiredError even for empty text.

Data Model Changes

No persistence schema (the library is stateless). Two new in-memory shapes:

1. AnonymiseResult — @dataclass(slots=True, frozen=True) (approved-versions mandate)

FieldTypeMeaning
anonymised_textstrFinal output: pseudonymised, then generalised when generalise=True.
detectionstuple[DetectedEntity, ...]Merged, start-ordered, non-overlapping spans. Tuple (not list) so the frozen result is not mutable through its fields.
audit_recordstuple[AuditRecord, ...]One per replaced span, document order; aligned 1:1 with detections. Carried because the regime report references them and consumers persist them beside the chain row. (Additive over AC1's minimum surface.)
audit_rowChainedRowThe appended hash-chain link; result.audit_row["hash"] feeds the next call's prev_hash.
complianceComplianceReport | NoneNone unless a regime was passed.

2. Audit-chain payload (the dict[str, JsonValue] given to append_row)

{
  "generated_at":      <caller-supplied str, echoed verbatim>,
  "doc_hash":          hash_text(original_text),      # SHA-256 commitment to the input
  "anonymised_hash":   hash_text(anonymised_text),    # SHA-256 commitment to the output
  "entities_detected": len(detections),               # int
  "entity_summary":    {"IN_AADHAAR": 1, ...},        # Counter dict of entity_type -> count
  "generalised":       true | false,                  # which mode produced the output
  "regime_id":         "DPDP-2023" | null,            # Regime.regime_id when given
  "compliant":         true | false | null            # report.compliant when a regime ran
}

PII rule: the payload carries counts, flags, and SHA-256 commitments only — never original values, never pseudonym tokens, never span positions. The two hashes bind the row to a specific input/output pair (an auditor holding the documents can re-derive and verify; an attacker holding only the chain learns nothing — SHA-256 preimage resistance, reusing core.doc_hasher.hash_text, the same primitive the chain itself uses). Canonical-JSON key sorting in append_row makes entity_summary insertion order irrelevant, so the row hash is fully deterministic.

API Contract Changes

Additive only — no existing signature changes. New public function + the first stable top-level export surface:

# packages/python-core/biltiq_privacy/pipeline.py
def anonymise(
    text: str,
    *,
    detector: Detector,                 # injected backend (PresidioDetector or custom)
    key: bytes | str,                   # HMAC key; empty -> HMACKeyRequiredError (fail-fast)
    generated_at: str,                  # REQUIRED, caller-supplied; library reads no clock
    regime: Regime | None = None,       # opt-in compliance attestation
    generalise: bool = True,            # False == CDSCO "pseudonymise_only" mode
    prev_hash: str = GENESIS_PREV_HASH, # chain continuation; default starts a new chain
) -> AnonymiseResult: ...

__all__ = [  # sorted() — pinned by test_public_all_matches_documented_surface
    "AnonymiseResult",
    "AuditRecord",
    "ChainedRow",
    "CheckStatus",
    "ComplianceCheck",
    "ComplianceReport",
    "DPDPRegime",
    "DetectedEntity",
    "Detector",
    "GENESIS_PREV_HASH",
    "HMACKeyRequiredError",
    "MissingNERModelError",
    "PresidioDetector",
    "Regime",
    "VerifyReport",
    "__version__",
    "anonymise",
    "verify_chain",
]

Rationale by group: facade (anonymise, AnonymiseResult); detection seam (Detector, DetectedEntity, PresidioDetector); regimes (Regime, DPDPRegime, ComplianceReport, ComplianceCheck, CheckStatus); errors (HMACKeyRequiredError, MissingNERModelError); audit chain (GENESIS_PREV_HASH, ChainedRow, VerifyReport, verify_chain); AuditRecord (element type of result.audit_records); __version__.

Deliberate exclusions (importable from their subpackages, not part of the top-level promise): Pseudonymiser, append_row, Detection (superseded by DetectedEntity at the facade), GeneralisationSpan, the six generalise_* field functions, hash_text/hash_document/hmac_pseudonymise, and everything under biltiq_privacy.indian. Keeping the top level to 18 names keeps the v0.1.0 compatibility surface small; power users keep the canonical biltiq_privacy.core / .indian imports, which remain public-but-namespaced.

No CLI changes, no env vars (the library reads no environment — key is injected, per the BILTIQ-007 contract).

Security & Compliance

  • Compliance mode: on_prem_preferred — the default path introduces zero network calls and zero AI dependencies beyond the already-ADR'd local Presidio/spaCy stack. The LLM contextual branch of CDSCO's pipeline is explicitly not ported (Phase D, injected-detector only). One gated exception (added 2026-06-11): PresidioDetector(auto_download_model=True) may download en_core_web_sm on first detect() — explicit per-instance opt-in, default False, guard-tested, recorded in ADR-0006.
  • No clock, no environment, no I/O in the facade: generated_at and prev_hash are caller-supplied; the key is an injected kwarg, never read from env inside python-core (BILTIQ-007 rule). The function is pure given its inputs.
  • Key handling: the key is passed straight to Pseudonymiser(key=key), validated before any text is touched (HMACKeyRequiredError on empty), never stored on the result, never logged, never embedded in the audit payload.
  • No PII in the audit payload: counts, booleans, regime_id, and SHA-256 commitments only (see Data Model). Pseudonym tokens and span positions are deliberately excluded from the chain row; they live in result.audit_records, which the consumer routes to access-controlled storage.
  • Result object PII surface: detections necessarily carry original span text (the detector contract); the result does not echo original_text (CDSCO did). README documents that detections are sensitive and must not be logged raw — pair with RedactionFilter.
  • Lazy-import gate (AC4): subprocess probe pins that import biltiq_privacy loads no presidio_analyzer, spacy, fastapi, or PDF/LLM/DB module.
  • Input escaping: not applicable — pure text-to-text library, no markup/SQL/shell sinks.

Performance Considerations

The hot path is detection (spaCy NER inside engine.analyze), unchanged by this task; the Presidio engine remains an instance-level lazy singleton (first detect() pays the ~1–2 s model load, subsequent calls do not). The facade adds: one sort + single pass for merge (O(k log k) in detection count k), the existing end-to-start string rebuild in pseudonymise_text (O(n·k) worst case on document length n), and generalise_text's per-span in + str.replace(token, …, 1) (O(n·k)). At document scale (the CDSCO production workload this ports) these string costs are negligible against NER; no optimisation warranted at v0.1.0. append_row is one SHA-256 over prev_hash + canonical_json(payload) — the payload is bounded (counts + two hashes), not document-sized. Empty-text short-circuit avoids the model load entirely for blank inputs.
