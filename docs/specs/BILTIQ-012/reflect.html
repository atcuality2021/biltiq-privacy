What went well

  • The plan-reviewer paid for itself again — round 1 finding #1 was the task's only HIGH defect. The direct-URL en-core-web-sm dependency would have passed every local gate (build succeeds, wheel imports) and failed only at the actual PyPI upload — the one mechanic that cannot be dry-run. Caught at planning, fixed as Step 4, gate-tested at the METADATA level (the exact defect class, not a proxy). Second consecutive task (after BILTIQ-011's AirIndia catch) where the reviewer found a real ship-blocking issue all tests would have missed.
  • GeneralisationSpan's docstring assigned the zip-assembly to "the orchestrator (BILTIQ-012)" back in BILTIQ-008 — the cross-task contract was written down where the next implementer would read it, and the facade slotted in with zero re-derivation. Forward-pointing docstrings on seams compound.
  • Fake-detector unit layer + real-stack e2e layer split. 14 orchestration tests run in 0.03 s with no model load; 3 e2e tests pay the spaCy cost once (module-scoped fixture). The split also localised the merge-policy surprise to the e2e layer where it belongs.
  • zip(..., strict=True) as a load-bearing assertion. Ruff's B905 nudge became a real invariant guard: a future ordering-contract break in the merge or the pseudonymiser now raises loudly instead of silently mispairing tokens.
  • Live-probing the merge before pinning expectations. When the e2e test failed (2 IN_* types missing), a 10-line probe against real detector output revealed the two overlap contests (UK_NHS tie, PERSON engulfment); the test was rewritten to characterise reality, and the code reviewer independently re-verified the characterisation against live output.
