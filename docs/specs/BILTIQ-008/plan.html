Step 1 — core/generaliser.py: the six field generalisersM

Rationale: The leaf primitives the dispatch layer (Step 2) routes to. Near-verbatim lift of the six CDSCO functions, with the one decoupling delta on generalise_location (inject-with-default region_map). Self-contained; depends on nothing in this task. Est. ~45 min.

Files: CREATE packages/python-core/biltiq_privacy/core/generaliser.py — SPDX header, module docstring naming the CDSCO origin + the AC5 no-overclaim note (rule-based generalisation, NOT a dataset-level k-anonymity guarantee; measurement is BILTIQ-021); from __future__ import annotations; import re; module-level _AGE_BRACKETS and default _REGION_MAP (verbatim, 21 states); the six functions generalise_age, generalise_date, generalise_location(location, *, region_map=None), generalise_phone, generalise_aadhaar, generalise_pan. CREATE packages/python-core/tests/core/test_generaliser.py (field-generaliser cases below).

Tests (each function: success path + fallback path + irreversibility — AC1, AC6):
  • test_generalise_age_brackets — 35→"20-39", boundaries 0→"0-19", 19→"0-19", 20→"20-39", 79→"60-79" (AC1).
  • test_generalise_age_overflow_floor — 80→"80+", 120→"80+", and the documented quirk -5→"80+" (no negative-redaction path; pins fall-through behaviour verbatim).
  • test_generalise_date_ddmm — "15/03/2020"→"March 2020", "01-12-1999"→"December 1999" (DD/MM ordering pinned per dev decision 2026-06-01).
  • test_generalise_date_redacted_fallback — malformed "not a date"→"[DATE_REDACTED]"; and the DD/MM consequence "05/13/2020"→"[DATE_REDACTED]" (group(2)=13>12), documenting that MM/DD input is redacted, not mis-mapped.
  • test_generalise_location_known_state — "AIIMS Delhi"→"Healthcare Facility, North India", "Kochi, Kerala"→"Healthcare Facility, South India" (substring match, AC1).
  • test_generalise_location_unknown_fallback — "Somewhere"→"Healthcare Facility, India" (no state matched).
  • test_generalise_location_region_map_override — passing region_map={"narnia":"Far North"} routes "Narnia clinic"→"Healthcare Facility, Far North" and the bundled Indian states no longer match (AC4 inject-with-default seam).
  • test_generalise_phone — "9876543210"→"+91 XXXXX XX210" (success); "12"→"[PHONE_REDACTED]" (<3 digits, fallback).
  • test_generalise_aadhaar — "1234 5678 9012"→"XXXX XXXX 9012" (success); "12"→"[AADHAAR_REDACTED]" (<4 digits, fallback).
  • test_generalise_pan — "ABCDE1234F"→"XXXXX1234X" (success, exactly 10 chars); "ABC"→"[PAN_REDACTED]" (wrong length, fallback).
  • test_irreversibility — for age/phone/aadhaar/pan, the exact input value is NOT a substring of the output and cannot be reconstructed from the coarsened form alone (AC6, per-value property only — not a dataset k-anonymity claim).
  • test_module_is_pure — static source-assertion: generaliser.py's import lines reference only stdlib (re, __future__, typing); no settings/os.environ/config/FastAPI/Pydantic/SQLAlchemy/LLM import (AC3). Mirrors the BILTIQ-007 test_no_settings_or_env_import shape — mypy alone does not verify import provenance, so this is the gate for the framework-free invariant.

Gate: pytest packages/python-core/tests/core/test_generaliser.py — GREEN; mypy --strict clean on the new module.

Step 2 — GeneralisationSpan + dispatch table + generalise_textS

Rationale: The orchestration layer over Step 1's primitives. Adds the typed input contract BILTIQ-012 will assemble and consume. Depends on Step 1. Est. ~30 min.

Files: EDIT packages/python-core/biltiq_privacy/core/generaliser.py — add the GeneralisationSpan(TypedDict) {entity_type: str, text: str, pseudonym_token: str}; the _GENERALISER dispatch dict (7 keys verbatim: IN_AADHAAR, IN_PAN, IN_PHONE, PHONE_NUMBER, LOCATION, ADDRESS, HOSPITAL); and generalise_text(pseudonymised_text, spans, *, region_map=None) — bounded str.replace(token, generalised, 1) per span, skipping unknown entity types and absent tokens. region_map is threaded into the LOCATION/ADDRESS/HOSPITAL dispatch calls. EDIT packages/python-core/tests/core/test_generaliser.py (dispatch/orchestration cases below).

Tests (AC2, AC4, AC6):
  • test_generalise_text_multi_span — two spans (e.g. a PHONE_NUMBER token + a LOCATION token) both replaced once each; output contains the generalised forms and neither pseudonym token survives (AC2 success path).
  • test_generalise_text_unknown_entity_skipped — a span with entity_type="PERSON" (not in _GENERALISER) leaves its token untouched in the output (failure/skip path).
  • test_generalise_text_absent_token_noop — a span whose pseudonym_token is not present in the text leaves the text unchanged (guard path).
  • test_generalise_text_empty_spans — empty span list returns the input text verbatim.
  • test_generalise_text_region_map_propagates — a custom region_map passed to generalise_text reaches the location dispatch and changes a LOCATION span's generalised value (AC4 seam end-to-end).
  • test_dispatch_table_keys — _GENERALISER has exactly the 7 expected keys mapped to the 3 expected callables (pins the table intact; no phantom ABHA).

Gate: pytest packages/python-core/tests/core/test_generaliser.py — GREEN; mypy --strict clean (no Any, no type: ignore).
