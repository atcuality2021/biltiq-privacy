Outcome

Shipped the REST sidecar (biltiq-privacy-server) over the framework-free engine: /detect, /anonymize, /validate (Bearer-JWT, verify-only) and an open /healthz. 8 atomic build steps, one commit each (code + tests + docstrings per step). Final battery: 68 server tests @ 99.39% coverage, 240 python-core tests (no regression), mypy --strict clean, ruff clean, deprecation-free. All 9 CI cells green across the 3.11–3.14 matrix.

All 12 acceptance criteria DONE — demonstrated live (AC1–6/9/11) and by test evidence (AC7/8/10/12).

What went well

  • Atomic-step discipline held under a context compaction mid-build. One commit per plan step, each green before commit, meant the two compactions (during Step 6 and now) landed on clean boundaries — no half-built step to reconstruct.
  • The design's "alternatives considered" caught the uvicorn fork trap early. Launching uvicorn by import string ("biltiq_privacy_server.app:app") rather than the live app object is what makes --workers > 1 re-import per fork (re-reading secrets, re-loading the model). Passing the object would have silently broken multiprocess serving — flagged at design, not discovered at runtime.
  • Recognising settings never enter the OpenAPI schema (AC9). Because Settings only reach app.state, any valid settings reproduce the committed contract — so the README regen one-liner is self-contained (no env, no test import) and no secret can leak into openapi.json. The drift test deep-equals parsed dicts, so formatting never false-fails.
  • Verify-only JWT closed alg-confusion by construction. Single-element algorithms=["HS256"] as a module constant (not a caller arg), no jwt.encode in production. Review slice A (the security slice) returned approved with zero AP#5 findings; none/HS512 rejection is test-pinned.
  • Degraded-start over crash-loop. A missing NER model starts the server degraded (/healthz + data endpoints → 503) instead of restart-looping; the real-lifespan degraded test gives lifespan.py 100% coverage.
  • Parallel 4-slice review (auth / app-CLI / models-routers / packaging-docs) surfaced every real finding in one pass and isolated the security surface to a dedicated reviewer.

What went wrong (caught in self-review / Review / Test)

  • Anti-Pattern #1 (Duplication) near-miss — documenting non-existent symbols. My first stack.md internal-module rows cited require_jwt in auth.py (it lives in dependencies.py) and get_pseudonymiser (the real seam is get_hmac_key). Caught by my own grep during Step 8 self-review and corrected before commit. Wrong doc pointers are worse than none.
  • Design↔code signature drift. design.html listed verify_token(token, *, secret, algorithm); the implementation pins the algorithm as a constant (safer — cannot be widened per call). Caught in Review slice A (minor); reconciled the design to match the code.
  • cli.py serve-only dispatch flagged. Review noted if command == "serve" has no else; confirmed correct as-is — required=True on the subparser makes any other command unreachable, so an else would be AP#6 dead code.

What we missed (slipped past, recurred, or only caught late)

  • The memory-curator silently strips the manual ADR-0007 line from MEMORY.md "Recent decisions" — and it recurs. The link was committed correctly at Step 8, then reverted in the working tree post-commit; review slice D flagged it (major); after restoring it, the curator stripped it again. Root cause: the curator rebuilds MEMORY.md and "Recent decisions" is not sourced from the memory-stream, so hand-edits are non-durable. This is the highest-value miss — it would silently erase decision history on any future curator run.
  • AC10 "socket guard on the detect path" is satisfied structurally, not explicitly. Network-freedom comes from TestClient's in-process ASGI transport + the FakeDetector seam (no model load), not a pytest-socket guard. The substantive AC10 requirements are met, but the literal wording implied an explicit guard that does not exist. Noticed at Test, not Review.

Process changes proposed (pending Friday review)

  • MEMORY.md "Recent decisions" durability. Make decisions durable against the curator: either source "Recent decisions" from task_state_change/decision events in the memory-stream, wrap the section in an auto: marker block, or document that decisions must be recorded via scripts/_memory_writer.write_event — never hand-edited. Without this, ADR links keep getting wiped.
  • Explicit no-network guard for server tests. Add pytest-socket disable_socket() (allow the in-process TestClient transport) so "no real network" claims like AC10 are enforced, not merely structural.
  • Doc-symbol citation already covered by review. Slice D verified every stack.md-cited symbol exists — keep that as a standing reviewer check; no new gate needed, but worth noting the AP#1 near-miss is exactly what that check catches.
