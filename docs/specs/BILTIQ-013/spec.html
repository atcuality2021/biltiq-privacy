Problem

biltiq-privacy v0.1.0 is now published and covers the full privacy pipeline (detect → pseudonymise → generalise → DPDP validate → audit chain). It is Python-only. The polyglot SDK plan (Node/PHP/Go, v0.1.1+) requires an HTTP interface. Consumers in non-Python stacks — ATC CommandCenter (Node), ManthanQuant (mixed), CDSCO-RegAI (Python but containerised separately) — must be able to call the privacy engine over REST without embedding the Python runtime.

The packages/python-server/ skeleton was scaffolded in BILTIQ-001 with FastAPI + uvicorn + pydantic v2 declared but no routes implemented. This task fills it in.

User Impact

External. Any consumer in any language can POST /anonymize with a JSON body and receive anonymised text + audit row + compliance report. The three endpoints cover the complete surface a polyglot SDK needs. JWT Bearer auth protects all three endpoints; GET /healthz is unauthenticated (load balancer / container probe).

Deployment paths: pip install biltiq-privacy-server && biltiq-privacy-server serve (native, preferred) or docker run biltiq/privacy-server:0.1.0 (offered).

Design Constraints (ruling before design)

  • Thin shim only. The server translates JSON ↔ library calls. No business logic, no regime implementation, no recogniser code lives here. Every privacy operation delegates to biltiq_privacy.*.
  • HMAC key never travels over the wire. BILTIQ_HMAC_KEY env var, read once at startup, injected via FastAPI Depends(). Callers do not supply a key in the request body.
  • JWT secret in env. BILTIQ_JWT_SECRET env var (HS256). Callers supply Authorization: Bearer <token>. The server verifies signature + expiry; it does not issue tokens (token issuance is the consumer's concern).
  • NER model loaded once at startup. PresidioDetector is instantiated during app startup; a missing en_core_web_sm surfaces as a startup-time 503 Service Unavailable (not a per-request 500).
  • generated_at is caller-supplied or server-clock. If the caller omits generated_at, the server supplies datetime.now(timezone.utc).isoformat() (the server is a system boundary — it may read the clock; the library underneath stays pure).
  • Audit chain is caller-owned. The server appends one row per /anonymize call and returns it; the caller persists the rows. The server holds no state between requests.
  • Pydantic v2 API only. model_validate, model_dump, field_validator — never v1 aliases (.parse_obj, .dict(), @validator).

Acceptance Criteria

HIGH-RISK ticket (auth path). Mandatory human plan review before Step 3 Build begins. Skill review does not substitute.
  • DONEAC1 — /detect endpoint. POST /detect runs PresidioDetector(score_threshold=...).detect(text) and returns a JSON array of detections. Optional score_threshold overrides the default (0.5). Empty text returns {"detections": [], "count": 0}. Requires valid JWT Bearer.
  • DONEAC2 — /anonymize endpoint. POST /anonymize calls biltiq_privacy.anonymise() with the server-injected HMAC key; returns the full AnonymiseResult serialised as JSON including audit_row. Missing generated_at defaults to server UTC clock. Missing prev_hash defaults to GENESIS_PREV_HASH. Requires valid JWT Bearer.
  • DONEAC3 — /validate endpoint. POST /validate instantiates the named regime and calls regime.validate(original_text, anonymised_text, detections, audit_records, generated_at=...); returns the ComplianceReport serialised as JSON. Unknown regime ID returns 422 Unprocessable Entity. Requires valid JWT Bearer.
  • DONEAC4 — /healthz probe. GET /healthz returns 200 {"status": "ok", "version": "0.1.0"} when the NER model loaded successfully at startup. Returns 503 if startup failed. No auth required.
  • DONEAC5 — JWT Bearer auth. All three data endpoints verify Authorization: Bearer <token> using BILTIQ_JWT_SECRET (HS256). Missing or invalid token → 401. Expired token → 401. The server never issues tokens. A missing BILTIQ_JWT_SECRET env var at startup raises RuntimeError (fast-fail before binding the port).
  • DONEAC6 — HMAC key injection. BILTIQ_HMAC_KEY env var is read once at startup and injected into every /anonymize call via Depends(). The key never appears in request bodies, response bodies, or logs. Missing env var at startup → RuntimeError (fast-fail). A key shorter than 32 bytes → RuntimeError at startup.
  • DONEAC7 — NER model startup load. The FastAPI app's startup event calls PresidioDetector().detect("") to trigger the engine build and cache it as an app-state singleton. A MissingNERModelError sets an app-state flag; /healthz returns 503 and all three data endpoints return 503 until a restart with the model present.
  • DONEAC8 — CLI entry point. biltiq-privacy-server serve [--host HOST] [--port PORT] [--workers N] starts uvicorn. Default: 0.0.0.0:8088, 1 worker. pyproject.toml [project.scripts] entry registered.
  • DONEAC9 — OpenAPI schema exported. GET /openapi.json returns the FastAPI-generated schema. Schema is committed to packages/python-server/openapi.json (used by SDK generator in v0.1.1+). Schema is regenerated in CI via a test assertion that compares the live schema to the committed file.
  • DONEAC10 — Tests with TestClient; no real network. All tests use fastapi.testclient.TestClient. No real uvicorn, no real network. BILTIQ_HMAC_KEY and BILTIQ_JWT_SECRET are monkeypatched to deterministic test values. ≥ 90% line coverage on biltiq_privacy_server/. Full suite green with no network access (socket guard on the detect path).
  • DONEAC11 — Error shape consistency. All error responses follow {"detail": "...", "code": "..."}. HMACKeyRequiredError from the library → 500 (should never reach the caller; indicates a server misconfiguration). MissingNERModelError → 503. Pydantic validation failures → FastAPI's default 422.
  • DONEAC12 — Packaging. packages/python-server/pyproject.toml version is 0.1.0. pip install biltiq-privacy-server succeeds in a clean venv with biltiq-privacy pre-installed. CHANGELOG.md entry added. README.md updated with server quickstart (install + env vars + serve command + one curl example per endpoint).

Out of Scope

  • Token issuance / OAuth2 flows — the server verifies JWTs; it does not mint them.
  • Rate limiting, request queuing, async workers — v0.2.0 concern.
  • Audit row persistence — the server returns the row; the caller persists it.
  • GDPR / HIPAA / CCPA regime support — Phase C (BILTIQ-017/018/019). Only DPDP-2023 is a valid regime ID in v0.1.0; unknown regime IDs return 422.
  • Multi-detector support via request body — only PresidioDetector in v0.1.0.
  • Node / PHP / Go SDK generation — v0.1.1+ (BILTIQ-016); this task produces the openapi.json those SDKs will generate from.
  • Docker image — offered but not built in this task; Dockerfile scaffolded only.
  • RedactionFilter on server logs — still PLANNED; log lines must not emit PII until it ships.
