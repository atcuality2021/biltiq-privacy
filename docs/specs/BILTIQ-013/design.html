Chosen Approach

Name

App-factory thin shim: create_app() + per-endpoint routers + a startup lifespan that builds the PresidioDetector singleton into app.state, with all privacy work delegated to biltiq_privacy.*. The server contributes zero privacy logic — it only translates JSON ↔ library calls and maps library exceptions to HTTP status codes.

Description

The package biltiq_privacy_server/ is organised as a factory, not a module-level app singleton. create_app(settings: Settings) -> FastAPI reads validated config, registers routers, installs exception handlers, and attaches the ASGI lifespan. A module-level app = create_app(load_settings()) is exposed only for uvicorn's import string; every test builds its own app from a test Settings so no global state leaks across tests (AC10).

Lifespan / startup singleton (AC7). A FastAPI lifespan async context manager (the approved replacement for the deprecated @app.on_event("startup")) runs once before the port binds. It constructs PresidioDetector(score_threshold=...) and calls .detect("") to force the spaCy/Presidio engine build (the library's instance-level lazy singleton). On success it stores the detector on app.state.detector and sets app.state.ner_ok = True. If the library raises MissingNERModelError, the handler catches it, sets app.state.ner_ok = False and app.state.detector = None, and logs the remedy (no PII). The app still starts so /healthz can report 503 and the three data endpoints can return 503 until a restart with the model present — a degraded-but-observable boundary rather than a crash loop.

Config & fast-fail secrets (AC5, AC6). config.py defines a frozen Settings (a plain pydantic v2 BaseModel with a field_validator, not pydantic-settings — that dep is not in stack.md and a single env read needs no extra library). load_settings() reads BILTIQ_JWT_SECRET and BILTIQ_HMAC_KEY from os.environ exactly once and constructs the model; construction raises RuntimeError if either var is missing, and the HMAC validator raises RuntimeError if the key is shorter than 32 bytes. load_settings() runs at import time of the app module, so a misconfigured deployment fails before uvicorn binds the port.

Depends() chain. Three dependency providers in dependencies.py read from request.app.state / the cached settings (never from the request body):

  • require_jwt — extracts the Bearer token via FastAPI's HTTPBearer(auto_error=False) security scheme, verifies it with PyJWT against the JWT secret (HS256, verify_exp on), and returns the decoded claims. Missing/invalid/expired → 401. This Depends is attached to all three data routers and to nothing on /healthz.
  • get_hmac_key — returns settings.hmac_key (bytes) for injection into /anonymize; the key is never serialised, never logged, never read from a request field (AC6).
  • get_detector — returns app.state.detector, or raises MissingNERModelError (→ 503 via the handler) when app.state.ner_ok is False, so every data endpoint shares the AC7 degraded gate uniformly.

Router organisation. One router file per endpoint under routers/ (detect.py, anonymize.py, validate.py, health.py), each an APIRouter with explicit response_model and status_code. The three data routers declare dependencies=[Depends(require_jwt)] at the router level so auth cannot be forgotten on an individual route; health.py has no auth dependency. This keeps each handler a ~10-line translate-and-delegate function and makes the auth boundary auditable at a glance (one grep for the data routers' dependencies=).

Model layer (models.py). Pydantic v2 request/response models mirror the library's TypedDicts and frozen dataclasses one-to-one. Library types stay authoritative; the pydantic models are a serialisation boundary only. Responses are assembled by reading the frozen AnonymiseResult / ComplianceReport dataclass fields and the DetectedEntity / AuditRecord / ChainedRow dicts into the matching pydantic model via model_validate (TypedDicts are plain dicts at runtime, so they validate directly). The server defines no privacy data shapes of its own beyond these wire mirrors.

Regime registry. A one-entry mapping _REGIMES: dict[str, type[Regime]] = {"DPDP-2023": DPDPRegime} in regimes_registry.py, with a resolve_regime(regime_id) -> Regime helper that instantiates the class with defaults or raises a UnknownRegimeError (→ 422). The registry is the single seam where Phase C regimes (GDPR/HIPAA/CCPA) slot in later; today only DPDP-2023 is valid per spec § Out of Scope.

Error-to-HTTP mapping (errors.py). Registered exception handlers convert library exceptions into the uniform {"detail": ..., "code": ...} envelope (AC11): MissingNERModelError → 503, HMACKeyRequiredError → 500 (a server misconfiguration that should never reach a caller), UnknownRegimeError → 422, JWT failures → 401, and pydantic RequestValidationError → 422 reshaped into the same envelope.

generated_at boundary. The server is a system boundary, so when a request omits generated_at the handler supplies datetime.now(timezone.utc).isoformat() before calling the (clock-free) library — the only place the server reads a clock, isolated to the two handlers that need it (dev ruling 2026-06-21).

Alternatives Considered

#AlternativeWhy Rejected
1python-jose[cryptography] for JWTDev-confirmed PyJWT >= 2.8 (2026-06-21). python-jose has a slower release cadence and a history of key-confusion / algorithm-confusion CVEs; PyJWT is lighter, actively maintained, and sufficient for HS256 verify-only. See ADR-0007 draft below.
2Module-level app = FastAPI() singleton with decoratorsA global app forces global config and makes TestClient tests share state (env, detector singleton). 3Lazy first-request model loadSpec AC7 + the constraint require startup load: a missing model must surface as a startup-time 503, not a per-request 500 on the unlucky first caller. Lazy load also pays the ~1–2 s NER build inside a request, blowing the first request's latency budget.
4HMAC key in the request bodyDev-ruled out: the key never travels over the wire. It is read once from BILTIQ_HMAC_KEY at startup and injected via Depends(); a body field would log-leak and force every caller to hold the secret.
5One fat router with all four endpointsMixes the auth boundary (three endpoints need JWT, /healthz must not) in one file, making it easy to attach/forget auth on the wrong route. Per-endpoint routers put dependencies=[Depends(require_jwt)] at the router level for the three data endpoints and leave health auth-free — auditable in one read.
6pydantic-settings BaseSettings for configNot in stack.md and adds a dependency for two env reads. A plain pydantic BaseModel + a load_settings() that reads os.environ covers it and keeps the fast-fail logic explicit and testable via monkeypatch (AC10).
7async def handlers calling the sync library directlyPresidio/spaCy detection is sync and CPU-bound; running it inline in the event loop blocks every other request. Plain def handlers let FastAPI run them in its threadpool (see Performance).

Data Model / API Contract

No persistence schema — the server is stateless (audit rows are returned, not stored; spec constraint). The only new shapes are the pydantic v2 wire models in models.py, each a thin mirror of an authoritative library type. v2 API only: model_validate / model_dump / field_validator — never parse_obj / .dict() / @validator (approved-versions § Pydantic v1→v2).

Element models (mirror the library record types)

Pydantic modelMirrors (library)Fields
DetectionModelDetectedEntity (TypedDict: entity_type, text, start, end, score, source)same six keys; score: float
AuditRecordModelAuditRecord (TypedDict: entity_type, pseudonym_token, position_start, position_end, confidence)same five keys
AuditRowModelChainedRow (TypedDict: prev_hash, payload, hash)prev_hash: str, payload: dict[str, JsonValue] (typed alias, no Any), hash: str
ComplianceCheckModelComplianceCheck (frozen dataclass)check_id, name, description, status, details, section, evidence: tuple[str,...]
ComplianceReportModelComplianceReport (frozen dataclass; note score is a property)regime_id, compliant, passed, total, checks, generated_at, frameworks + computed score echoed in the response

Serialisation strategy (dataclass / TypedDict → pydantic)

  • TypedDicts (DetectedEntity, AuditRecord, ChainedRow) are plain dicts at runtime → DetectionModel.model_validate(det) validates each directly; no manual field copying.
  • Frozen dataclasses (ComplianceReport, ComplianceCheck) are not dicts → a small converter reads named fields and builds the model, or ConfigDict(from_attributes=True) + model_validate(report). The derived score property is read explicitly and placed in the response (pydantic does not see dataclass @property).
  • AnonymiseResult (frozen dataclass) → AnonymizeResponse field-by-field: anonymised_text, list of DetectionModel, list of AuditRecordModel, AuditRowModel, optional ComplianceReportModel.

Security & Compliance Notes

Compliance mode: on_prem_preferred. The sidecar makes no cloud / external AI calls. It wraps the same local Presidio/spaCy stack the library already uses; PyJWT is a local crypto library, not a network dependency. No ADR-blocking violation; the one new dependency (PyJWT) gets ADR-0007 per the repo rule that new deps are documented.

JWT verification flow (AC5)

  1. HTTPBearer(auto_error=False) extracts the Authorization: Bearer <token> value; absent → require_jwt raises 401.
  2. auth.verify_token calls jwt.decode(token, secret, algorithms=["HS256"], options={"verify_exp": True}) — algorithm is pinned to a single-element allow-list, closing the alg-confusion class.
  3. ExpiredSignatureError / InvalidTokenError → 401. Verify-only: the server never calls jwt.encode in production code (only the test fixture mints tokens).

Secrets & startup fast-fail (R1, R2)

  • BILTIQ_JWT_SECRET and BILTIQ_HMAC_KEY are read once in load_settings(); missing either → RuntimeError before the port binds (AC5/AC6). HMAC key < 32 bytes → RuntimeError.
  • Neither secret nor any Authorization header value is ever logged (R1). README/runbook documents sourcing both from a secrets manager, not a committed .env (R2).

No-PII-in-logs constraint (R3, R4)

  • RedactionFilter is still PLANNED (stack.md) — so the server must not log request bodies or detection values at any level until it ships. Handlers log only method + path + status + entity counts, never text, never detection spans, never tokens.
  • R4 mitigation: a ruff lint guard banning logger.debug(...request.*) patterns; test_no_pii_in_response.py asserts no synthetic PII value leaks into the audit_row payload (the library already guarantees the chain payload is PII-free) or into captured log records.
  • R3: the /detect and /anonymize responses necessarily carry detection spans (the detector contract) — this is inherent and documented, not a leak; callers route responses to access-controlled sinks.

Input handling: pure text-to-JSON; no SQL/shell/markup sink. Pydantic validates the request shape; oversized-body / rate-limiting are explicitly v0.2.0 (spec § Out of Scope).

Performance Considerations

Model load is a one-time startup cost. The lifespan handler pays the ~1–2 s spaCy/Presidio engine build once, before the port binds; the engine is cached on app.state.detector and reused for every request (the library's instance-level singleton). No request pays the build cost (the AC7 rationale for startup-over-lazy).

Sync handlers in a threadpool (decided). Presidio/spaCy detection is synchronous and CPU-bound. Handlers that touch the detector (/detect, /anonymize) are declared as plain def (not async def); FastAPI runs def handlers in its worker threadpool, so a slow detection does not block the event loop or other in-flight requests. Declaring them async def and calling the sync library inline would block the single event loop — the worst option. /validate (pure-Python regime checks, no model) and /healthz (flag read) are cheap; /validate stays def for consistency with the threadpool model, /healthz can be async def (trivial). True parallelism across CPU cores is the --workers N knob (AC8); the GIL bounds a single worker's threadpool, which is acceptable at v0.1.0 (no async workers / queue — spec § Out of Scope).

Hot path: detection inside engine.analyze (unchanged from the library); the server adds only JWT verify (one HMAC-SHA256 over the token — microseconds) and pydantic validate/dump (bounded by payload size). Latency budget is dominated by NER, identical to a direct library call plus a sub-millisecond auth + serialisation overhead.

ADR-0007 draft: JWT library selection

Status: Proposed (dev-confirmed PyJWT 2026-06-21; to be finalised at Ship).

Context. BILTIQ-013 adds Bearer-JWT auth to the FastAPI sidecar. The server must verify HS256-signed tokens (signature + expiry); it does not issue them (token minting is the consumer's concern). This needs a JWT library. The spec named two candidates and expressed a PyJWT preference; this ADR records the decision.

Decision. Use PyJWT >= 2.8, < 3 with HS256, verify-only. Verification pins a single-element algorithm allow-list (jwt.decode(..., algorithms=["HS256"], options={"verify_exp": True})) and the server contains no jwt.encode call in production code.

Alternatives. python-jose[cryptography] — rejected: slower release cadence and a history of key-confusion / algorithm-confusion CVEs; heavier dependency tree (cryptography backend) than needed for HS256 verify-only. Rolling our own HMAC verify — rejected: re-implementing JWT parsing/validation is exactly the kind of crypto-adjacent code that should reuse a maintained, audited library.

Consequences. (+) Lighter dependency, active maintenance, smaller attack surface, explicit algorithm pinning closes the alg-confusion class. (+) Verify-only keeps the server out of the token-issuance blast radius. (−) Consumers must mint tokens themselves (documented in README; aligns with the spec's out-of-scope on token issuance). (−) New runtime dependency added to pyproject.toml and recorded in approved-versions.md.

Thin-shim watch (duplication risks to flag)

  • Regime instantiation must stay a registry lookup → DPDPRegime(); the server must never re-implement or parametrise DPDP check logic. Only regimes_registry.py knows regime IDs.
  • generated_at default is the only clock read; do not let it spread into the library call path or into /validate's regime — the library stays pure.
  • Detection / merge / pseudonymise / generalise / chain all live behind biltiq_privacy.anonymise — /anonymize must call the facade, not re-chain the five wrappers (that would duplicate BILTIQ-012's orchestration).
  • HMAC key normalisation (str→bytes, empty check) belongs to Pseudonymiser; the server validates only length-at-startup and passes the key straight through.
  • Wire models mirror library types; if the library type changes, the model changes — do not let the two drift into independent shapes (a contract test on field names guards this).
