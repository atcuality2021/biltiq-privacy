What Went Well

  • Parallel review dispatch. Three biltiq-code-reviewer subagents ran simultaneously over the 21-file / 2,444-LOC diff, sliced by cognitive concern (production code / tests+fixtures / docs+harness). The per-slice briefs let me embed the user's standing real-PII forbidden-values list in the test-reviewer's prompt specifically — a single inline reviewer would have had a harder time keeping that hot. The grep returned not-found for all six forbidden values; if that had failed it would have been the highest-stakes find of the PR.
  • AC5 lazy-import contract paid off in a real way. Splitting patterns.py (stdlib re only) from recognisers.py (Presidio + spaCy) means a hot-path logging-filter consumer can import biltiq_privacy.indian.patterns and get the 8 regexes + redact() at sub-millisecond cost. Verified by a subprocess-isolated test with a positive control (test_recognisers_import_does_load_presidio) that catches vacuous-pass if the probe itself ever breaks. Worth repeating for any future regional pack (EU, US, UK).
  • CDSCO-RegAI provenance attribution in module docstrings. Every regex was a port, not a reinvention. Naming the source files (backend/utils/pii_patterns.py, backend/modules/anonymisation/presidio_engine.py) makes "where did this come from" traceable for the next maintainer. AC11 enforced this; without the explicit AC, the port could have looked like an original.
  • Step-9 harness diagnostic discipline. The tests/ namespace collision under repo-root pytest took four attempts to fix (PEP 420 namespace, then pythonpath, then regular __init__.py, then consider_namespace_packages=true). Diagnostic technique: temporary conftest.py print statements at three pytest lifecycle points (rootconftest load, pytest_configure, pytest_collectstart) pinpointed exactly when sys.modules['tests'] got locked with the wrong __path__. Without that, blind-guessing would have continued. Worth codifying as a "pytest namespace-collision diagnostic" recipe in a future skill.
  • AC3 invariant test via import-by-name. The chosen mitigation for "no regex string duplication" was structural — recognisers.py imports AADHAAR_PATTERN by name and passes it to Pattern(regex=...). The test asserts _AADHAAR.patterns[0].regex == AADHAAR_PATTERN (equality, deliberately not identity — Python string interning for non-pool strings is implementation-defined). A regression like inlining the literal in recognisers.py would still fail this test. The structural-plus-test combination is stronger than either alone.

Process Changes Proposed

  1. AGENT_RULES.md — new rule under § Build discipline: "When a Build step edits a file, grep design.html § Files to touch for that file path. If the row says 'no edit' or is missing, update the row in the same step. Doc-drift findings at Review are cheaper to prevent at Build." (Trigger: BILTIQ-002 Step 4 Review caught the mypy-override drift; would have been zero cost to fix at Step 9 if the Build skill had checked.)
  2. stack.md split into Shipped vs Planned tables. Current single-table format mixes shipped state (Presidio, RedactionFilter, biltiq_privacy.indian.*) with forward-looking rows (age, future core.time wrapper, v0.5.0+ encryption). A contributor reading stack.md cannot tell which is which without grepping the codebase. Proposal: add a (planned, v0.5.0+) tag column, or split into ## Shipped and ## Planned sections.
  3. Skill change — code-reviewer brief: bake in standing PII forbidden-values list. The Slice B (test+fixtures) review caught the no-real-PII guarantee because the brief explicitly named the six forbidden values from the user's earlier-session standing constraint. A future review where I forget to copy that list into the brief would silently lose this check. Proposal: have code-reviewer skill always emit a grep -F step against a per-repo .biltiq/forbidden-values.txt file (gitignored, per-machine) for test-fixture review slices.
  4. Skill change — document the pytest namespace-collision diagnostic recipe. The Step-9 four-attempt loop cost ~40 minutes of human-review time. A new skill pytest-import-mode-debug codifying the three-lifecycle-print-statement technique (rootconftest, pytest_configure, pytest_collectstart) would short-circuit future occurrences.
