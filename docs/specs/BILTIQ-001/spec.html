Problem

The biltiq-privacy repo currently contains documentation and BiltIQ engineering scaffolding only — no Python package structure. Nothing under packages/ exists yet, so consumers (CDSCO-RegAI, ATC CommandCenter, ManthanQuant, and future BiltIQ products) have no way to pip install biltiq-privacy or import the engine. The monorepo design (Python library + FastAPI sidecar + native SDKs per docs/architecture/overview.md) is documented but not skinned in code — every dependency pin, mypy/ruff config, package boundary, and CI matrix is sitting in prose. Until the skeleton lands, no port from CDSCO-RegAI (core/pii_patterns.py, regimes/dpdp.py, etc.) has anywhere to go.

User Impact

After BILTIQ-001 ships, the repo is importable but empty: pip install -e packages/python-core and pip install -e packages/python-server both succeed against Python 3.11/3.12/3.13/3.14, all pinned Presidio/spaCy/FastAPI deps resolve, mypy --strict passes on the (empty) packages, ruff passes, and CI is green on every supported interpreter. No end-user-visible privacy behaviour yet — that arrives starting in BILTIQ-002. The unblock: subsequent porting tasks (pii_patterns.py, recognisers/india.py, regimes/dpdp.py, etc.) have a fully-validated landing zone, so each port is a focused content change, not a structural one.

Acceptance Criteria

  • OPEN AC1 — Directory layout matches docs/architecture/overview.md: packages/python-core/biltiq_privacy/{core,recognisers,regimes,detectors,backup}/ and packages/python-server/biltiq_privacy_server/ exist with __init__.py files only.
  • OPEN AC2 — packages/python-core/pyproject.toml uses hatchling backend, declares requires-python = ">=3.11", and pins deps per docs/architecture/approved-versions.md: presidio-analyzer >=2.2,<3, presidio-anonymizer >=2.2,<3, spacy >=3.7,<4, en-core-web-sm bundled at 3.7.1, rapidfuzz >=3.0,<4.
  • OPEN AC3 — packages/python-server/pyproject.toml uses hatchling backend, depends on biltiq-privacy (workspace), fastapi >=0.110,<1, uvicorn[standard] >=0.27,<1, pydantic >=2.5,<3.
  • OPEN AC4 — pip install -e packages/python-core and pip install -e packages/python-server succeed on Python 3.11, 3.12, 3.13, and 3.14.
  • OPEN AC5 — mypy --strict packages/python-core packages/python-server passes.
  • OPEN AC6 — ruff check packages/ passes with rule set E, F, I, B, UP, DTZ (per AGENT_RULES.md).
  • OPEN AC7 — .github/workflows/ci.yml runs the 4-version Python matrix and is green on main. No continue-on-error entries.
  • OPEN AC8 — No file other than __init__.py exists under packages/python-core/biltiq_privacy/{core,recognisers,regimes,detectors,backup}/. Enforces scaffolding-only scope.
  • OPEN AC9 — Library/server boundary check: scripts/check-boundaries.sh exits non-zero if any file under packages/python-core/ imports fastapi, starlette, or uvicorn. CI invokes it.
  • OPEN AC10 — Running pip install -e . at the repo root installs both biltiq-privacy and biltiq-privacy-server in one command (hatch workspace pattern). Contributor onboarding works.

Out of Scope

  • No port of any module from CDSCO-RegAI (pii_patterns.py, log_filter.py, doc_hasher.py, pseudonymiser.py, generaliser.py, audit_chain.py) — those are BILTIQ-002+ tasks.
  • No recogniser implementations (recognisers/india.py etc.) — BILTIQ-002+.
  • No regime adapters (regimes/base.py, regimes/dpdp.py) — BILTIQ-002+.
  • No detector implementations (detectors/base.py, detectors/presidio_backend.py) — BILTIQ-002+.
  • No FastAPI routes (/anonymize, /validate, /healthz) — separate task once core is ported.
  • No native SDKs (packages/node, packages/php, packages/go) — v0.1.1+ scope.
  • No Dockerfile, no docker-compose.yml, no server/docker/ directory — separate task; native install is the primary path.
  • No PyPI release. v0.1.0 publication is a separate ship task (BILTIQ-00X-publish) after the engine actually works.
  • No tests beyond what's needed to validate pyproject.toml resolves (single tests/test_import.py per package asserting the package imports). No characterisation tests for engine behaviour — impossible, no engine yet.

Open Questions

  • None at spec-confirm. Pre-build risks (e.g., spaCy/Presidio wheel availability on Python 3.14) will be surfaced in design.html § Risks rather than left here.
