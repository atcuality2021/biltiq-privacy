Approach

Name

Stdlib-only JSONL append-stream + deterministic projection curator, with fcntl.flock advisory locking and an opt-in post-commit hook.

Description

Two small Python modules under a new scripts/ package, both stdlib-only (no new dependencies). scripts/_memory_writer.py exposes write_event(event_type, payload) that appends one JSON line to .biltiq/memory-stream.jsonl using a single os.write() against an O_APPEND file descriptor — POSIX guarantees the write is atomic for payloads under PIPE_BUF (4 KiB on Linux), and we cap a single event at that size to keep the guarantee. scripts/_memory_curator.py reads the stream end-to-end, projects events into a fixed set of auto-curated MEMORY.md sections delimited by HTML-comment markers, and writes the file back atomically (temp + os.replace). Manual content is fenced by <!-- manual:start -->…<!-- manual:end --> markers and copied through verbatim. Concurrency is protected by fcntl.flock(LOCK_EX|LOCK_NB) on .biltiq/.curator.lock; a second invocation finding the lock held prints {"skipped": "another curator already running"} to stdout and exits 0. The hook variant (scripts/hooks/post-commit.sh) is shipped but not installed; scripts/install-curator-hook.sh places it under .git/hooks/post-commit idempotently. Trade-off: we rebuild auto-sections from the full stream on every run rather than tail-following — simpler, deterministic, and well under the 200 ms budget for the foreseeable stream size (thousands of events ≈ hundreds of KB).

Alternatives Considered

#AlternativeWhy Rejected
1SQLite-backed event storeAdds query power we will not use in v1; turns the stream from a grep-able text file into an opaque binary; complicates the gitignore + per-machine backup story. JSONL is enough until we need filtered projections.
2filelock PyPI packageNew runtime dependency for what stdlib fcntl.flock already does on Linux/macOS (the only platforms the dev runs on). Adds a wheel + version pin + airgap-CI burden against a feature that has not been requested.
3os.O_EXCL lock-file race instead of flockLock leaks on crash; we would need a stale-PID-cleanup heuristic. fcntl.flock auto-releases when the file descriptor closes (including process exit / kill).
4Read-modify-write of MEMORY.md via regex section markersBrittle when the dev edits the file from the inside; one stray bracket and the regex eats manual content. HTML-comment delimiters are an explicit out-of-band contract neither Markdown renderers nor the dev's eye will trip over.
5JSONL append via Python open(..., "a")CPython buffers; two concurrent writers can interleave bytes mid-line. Going through os.open(..., O_WRONLY|O_APPEND|O_CREAT) + a single os.write() of the full line + "\n" bytes hits the POSIX atomic-append guarantee with no buffering layer in the way.
6Install the hook by defaultSpec OQ2 explicitly resolves “on-demand default, opt-in hook” — surprising the dev with a hook that runs on every commit violates least-astonishment, especially for collaborators cloning the repo.

Data Model

Event stream — .biltiq/memory-stream.jsonl

Append-only newline-delimited JSON. One event per line. UTF-8. No trailing comma, no enclosing array.

{
  "schema_version": 1,
  "ts": "2026-05-18T11:42:07.812000+00:00",
  "event_type": "standup_post",
  "payload": { ... event-type-specific keys ... }
}

Field rules:

  • schema_version: integer. v1 ships with 1. Bumped on any breaking change to the event schema. The curator skips events with schema_version > CURATOR_SUPPORTED_VERSION (forward-compat).
  • ts: ISO-8601 UTC, microsecond precision, produced by datetime.now(timezone.utc).isoformat() (current API per docs/architecture/approved-versions.md; datetime.utcnow() is on the deprecated list).
  • event_type: lowercase snake_case string. v1 vocabulary: standup_post, decision_made, blocker_logged, reflect_note, commit_metadata. Other values are written but ignored by the projector (AC4 forward-compat).
  • payload: arbitrary JSON-serialisable dict. Convention per event type:
    • standup_post → { "date": "YYYY-MM-DD", "did": [...], "doing": [...], "blockers": [...] }
    • decision_made → { "title": str, "rationale": str, "adr_ref": str | null }
    • blocker_logged → { "title": str, "task_id": str, "since": "YYYY-MM-DD" }
    • reflect_note → { "task_id": str, "what_went_well": [str], "what_broke": [str] }
    • commit_metadata → { "sha": str, "task_id": str | null, "files_touched": [str] }

Total event size hard cap: 4 KiB (PIPE_BUF on Linux). The writer measures the encoded line and raises MemoryEventTooLargeError if exceeded — this preserves the POSIX atomic-append guarantee for the single os.write(). The curator never enforces this cap on read (forward-compat).

MEMORY.md section-marker convention

The curator owns the contents of auto:<name> blocks. Everything else — including the file's top-of-file preamble — is untouched.

<!-- auto:current_focus:start -->
<!-- generated by scripts/_memory_curator.py; do not hand-edit -->
(projection output)
<!-- auto:current_focus:end -->

<!-- manual:start -->
## Recent decisions
(human-curated content, never touched by the curator)
<!-- manual:end -->

Fail-closed rule: if the curator cannot locate matching start/end markers for any of the auto-sections it intends to write, it exits non-zero with {"error": "missing_marker", "marker": "..."} on stderr and writes nothing. This protects manual content from regex-mishaps (Risk R1 below).

API Contract

Writer — Python

from __future__ import annotations
from typing import Any

def write_event(event_type: str, payload: dict[str, Any]) -> None:
    """Append one event to .biltiq/memory-stream.jsonl.

    Raises:
      ValueError: if event_type is empty or payload is not a dict.
      TypeError: if payload is not JSON-serialisable.
      MemoryEventTooLargeError: if the encoded line exceeds PIPE_BUF (4096 bytes).
      OSError: bubbled up unchanged from the filesystem layer.
    """

Repo-root resolution order: os.environ["BILTIQ_REPO_ROOT"] if set (tests use this) → the result of walking up from Path(__file__).resolve() looking for a .git/ or AGENT_RULES.md marker. Never reads any other env var; never touches network. No logging at INFO level (the writer is on the hot path of every workflow command); only WARNING+ if the write fails.

Curator — CLI

$ python3 scripts/_memory_curator.py [--verbose]
# Exit codes:
#   0  success (sections rewritten, or no-op if stream empty)
#   0  lock held by another process — stdout: {"skipped": "another curator already running"}
#   1  fail-closed: missing manual/auto marker; stderr: {"error": "...", "marker": "..."}
#   2  unrecoverable I/O error; stderr: {"error": "io", "detail": "..."}
# stdout (success): {"events_seen": N, "events_projected": M, "sections_written": [...]}

Note: exit 0 for the lock-contention path is deliberate — the standup command treats “another curator is already running” as success-with-no-work, not failure.

Hook — shell

# scripts/hooks/post-commit.sh
# Contract: never exits non-zero, never writes to stdout/stderr on the
# commit's TTY, never logs payload contents.
nohup python3 "$REPO_ROOT/scripts/_memory_curator.py" \
  >> "$REPO_ROOT/.biltiq/curator-hook.log" 2>&1 &
exit 0

Installer — shell

$ scripts/install-curator-hook.sh           # install (idempotent)
$ scripts/install-curator-hook.sh --uninstall  # remove the symlink
# Exit 0 on success; exit 1 on missing .git/ (not in a repo).
# Never overwrites a non-symlink .git/hooks/post-commit without --force.

Security & Compliance

  • Compliance mode: on_prem_preferred (per AGENT_RULES.md § Compliance). The writer + curator are pure-Python deterministic projection; no external AI, no cloud API, no network sockets opened, no subprocess except git rev-parse in the installer. Trivially compliant; we state it explicitly so the on-prem-compliance scanner does not have to re-derive it on every audit.
  • PII on the stream: payload contents are dev-authored prose (standup notes, decision rationales, blocker descriptions). They may contain @-mentions, internal task IDs, and free text that could include third-party names. Because biltiq-privacy exists to address exactly this class of leakage we eat our own dogfood: the stream stays per-machine (gitignored), and the committed projection (MEMORY.md) is curated by hand — the dev decides what crosses the trust boundary on every git commit they make to MEMORY.md.
  • Hook log hygiene: scripts/hooks/post-commit.sh writes only the curator's stdout + stderr to .biltiq/curator-hook.log. The curator's stdout is structured JSON containing event counts, not payload contents. Anti-Pattern #5 defence: if a future curator change starts logging payload bytes, the hook log must move under the same redaction discipline as core.log_filter — flagged here for the eventual reviewer.
  • Symlink install: install-curator-hook.sh refuses to overwrite an existing non-symlink post-commit hook without --force. Prevents silently clobbering a hook a dev or another plugin has installed.
  • Lock-file path: .biltiq/.curator.lock is created with mode 0600 (writer's umask notwithstanding) so collaborators on a shared dev box cannot DOS each other's curators.
  • No shell=True anywhere; the installer's git rev-parse call uses an argv list. No user-controlled string ever reaches a shell parser.
  • No print() from the writer: the writer is library-shaped (called by other tools); it uses logging.getLogger(__name__). The curator's stdout is structured JSON, which is its CLI contract, not freeform output.

Performance Considerations

  • Writer: a single os.open + os.write + os.close per event. No buffering, no read step. O(1) on stream size. Measured budget: < 1 ms per event on warm disk.
  • Curator: reads the full stream into memory once, projects, writes MEMORY.md atomically. Budget: < 200 ms for streams up to ~10,000 events (~ a year of solo dev activity); the curator is invoked at most once per commit when the hook is enabled, and on demand otherwise — the 200 ms cap keeps the hook from being a visible commit delay. Above ~10,000 events we will introduce incremental projection in a follow-up (out of scope for v1).
  • Lock acquisition: fcntl.flock(LOCK_EX | LOCK_NB) is < 1 ms; failure path (lock held) is even faster.
  • Hook detachment: nohup … & returns immediately; the curator runs in the background. The hook itself adds < 10 ms to the visible commit time.
  • No new dependencies means no import-time cost beyond stdlib; the writer's import path (from scripts._memory_writer import write_event) loads only json, os, pathlib, datetime.

Rollout Plan

  1. Step 1 — scaffold scripts. Add scripts/__init__.py, scripts/_memory_writer.py, scripts/_memory_curator.py. Delete the stale .biltiq/curator.lock. Add the writer + curator tests. Run them green. This satisfies AC1–AC6 and unblocks the biltiq-engineering plugin's /biltiq-engineering:standup "After posting" call — from this commit forward, every workflow command that emits an event starts persisting state to the stream.
  2. Step 2 — documentation hooks. Add the AGENT_RULES.md § Memory section. Surround manual content in MEMORY.md with the markers. Update .gitignore and docs/architecture/stack.md. Satisfies AC7.
  3. Step 3 — opt-in hook. Add scripts/hooks/post-commit.sh and scripts/install-curator-hook.sh with their tests. Satisfies AC8 + AC9. The dev runs the installer manually when they want background curation on every commit; CI does not install it.
  4. Acceptance check — AC5. After Step 1 lands, invoke /biltiq-engineering:standup in a real session; confirm an event lands in the stream and the curator completes without raising. This is a manual gate before closing the task.

Rollback

Revert the merge commit. The stream file (.biltiq/memory-stream.jsonl) is gitignored and per-machine; reverting the code leaves the stream in place but it becomes inert — no slash command tries to read or append once scripts/_memory_writer.py is gone, because the upstream plugin's call sites guard with try: from scripts._memory_writer import write_event … except ImportError: pass. MEMORY.md reverts to whatever content was in the commit prior; manual sections are preserved by virtue of being in a regular text file. Rollback is non-destructive.

Risks

IDRiskLikelihoodMitigation
R1 MEMORY.md auto-section regeneration corrupts manual content if start/end markers are missing or mis-paired. MED Curator fails closed: when any expected marker pair is missing, exit non-zero, write nothing, surface the marker name in stderr. Test test_memory_curator.py::test_missing_marker_fails_closed covers this directly. The first curator run after Step 2 lands is the highest-risk window — the dev verifies MEMORY.md by hand after the first commit that runs the curator.
R2 Lock file (.biltiq/.curator.lock) is orphaned by a crashed curator. LOW fcntl.flock releases the lock automatically when the holding process exits or is killed — no manual cleanup needed. Documented in the curator module's top-of-file docstring so the dev does not waste time hunting a phantom stale lock.
R3 The opt-in post-commit hook swallows a curator failure silently and the dev never notices state is being lost. MED Hook redirects curator stdout/stderr to .biltiq/curator-hook.log (append). The dev's standup template includes a one-line "tail -n 5 .biltiq/curator-hook.log" check. CI does not enable the hook; only the dev who explicitly opts in is exposed. If a follow-up wants visible failures, that is a separate task adding a one-line warning to the next git status — out of scope here.
R4 Collision with the upstream biltiq-engineering plugin's own auto-trigger paths. LOW The plugin's standup command already calls write_event + python3 scripts/_memory_curator.py in series; our lock serialises any concurrent invocation safely (second caller gets the skipped sentinel). The hook variant adds at most one curator process per commit; the lock makes it safe to overlap with a manual curator run. AC3 + AC6(d) tests cover this.
R5 Stream growth degrades curator latency past the 200 ms budget. LOW Budget headroom: ~10,000 events. At a realistic emission rate (~ 20 events / dev-day) we hit that in ~500 working days. Follow-up task to introduce incremental projection + archival is tracked under the existing “archive promotion” out-of-scope item in spec.html.
R6 POSIX atomic-append guarantee depends on payload size staying under PIPE_BUF; a careless caller could pass an oversize blob. LOW Writer measures the encoded line and raises MemoryEventTooLargeError with the offending event type and byte count in the message. Test test_memory_writer.py::test_oversize_raises covers this.
