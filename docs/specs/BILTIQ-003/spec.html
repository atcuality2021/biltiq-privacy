Problem

Several biltiq-engineering workflow commands (notably /biltiq-engineering:standup, and likely /biltiq-engineering:commit, /biltiq-engineering:reflect, and the auto-trigger paths) call into scripts/_memory_writer.py::write_event() and scripts/_memory_curator.py for the “After posting” memory-spine emission step. Neither script exists in this repo yet — BILTIQ-000 bootstrapped only the repo structure. Result: every workflow command that tries to emit a structured event silently no-ops, and MEMORY.md never receives the canonical event stream it was designed to be regenerated from. Across sessions, decisions, blockers, and standup history are lost or remembered only in free-form prose, which the curator cannot safely round-trip.

User Impact

Engineering team (currently @don007rvs solo, eventually shared) gets a working memory-spine for biltiq-privacy:

  • Standups, ADRs, and reflection notes append to .biltiq/memory-stream.jsonl as structured events.
  • The curator rebuilds MEMORY.md auto-curated sections from those events while preserving manually-edited sections verbatim.
  • Workflow commands that reference the memory-spine stop being silent no-ops.
  • Across sessions, blocker patterns and recent-decision context survive without manual MEMORY.md maintenance.

Acceptance Criteria

  • OPEN AC1 — scripts/_memory_writer.py exposes write_event(event_type: str, payload: dict) -> None that appends one JSON line to .biltiq/memory-stream.jsonl with fields: ts (ISO-8601 UTC), event_type, payload, schema_version. Append is atomic (write to temp + rename, or O_APPEND with a single write()).
  • OPEN AC2 — scripts/_memory_curator.py reads the memory-stream, projects events into auto-curated MEMORY.md sections, and writes the result. Manual sections (delimited by HTML comment markers <!-- manual:start --> / <!-- manual:end -->) are preserved verbatim across runs.
  • OPEN AC3 — The curator uses a file-based lock (.biltiq/.curator.lock via fcntl.flock). If a second invocation finds the lock held, it exits cleanly with {"skipped": "another curator already running"} — the standup command relies on this exact contract.
  • OPEN AC4 — Canonical event types for v1: standup_post, decision_made, blocker_logged, reflect_note, commit_metadata. Unknown event types are written to the stream but ignored by the curator (forward-compat).
  • OPEN AC5 — /biltiq-engineering:standup runs end-to-end without error: the “After posting” write_event("standup_post", ...) + python3 scripts/_memory_curator.py calls both succeed on a clean repo.
  • OPEN AC6 — Tests in tests/scripts/ cover: (a) write_event append + JSON round-trip, (b) curator regenerates auto-sections from the stream, (c) manual sections survive a curator run unchanged, (d) lock contention path returns the skipped sentinel without raising, (e) unknown event type is tolerated.
  • OPEN AC7 — .biltiq/memory-stream.jsonl is gitignored; MEMORY.md is committed. Documented in AGENT_RULES.md § Memory.
  • OPEN AC8 — An opt-in post-commit hook is provided at scripts/hooks/post-commit.sh. It is not installed by default; the dev enables it via scripts/install-curator-hook.sh (which symlinks or copies into .git/hooks/post-commit). When enabled, every successful commit runs the curator in the background — failures are logged to .biltiq/curator-hook.log but never block the commit.
  • OPEN AC9 — Tests cover the hook’s opt-in behaviour: install script idempotent, hook runs curator when enabled, no-op when disabled, hook failure does not abort the commit.

Out of Scope

  • Compact-then-brief auto-trigger (the hook that fires write_event + curator on session compaction) — that’s tracked in the biltiq-engineering plugin as BILTIQ-017g-phase2; this task only ships the local Python core it depends on.
  • Archive promotion from .biltiq/memory-archive/ to docs/memory-archive/ — deferred; the archive-commit skill handles it once the stream exists.
  • LLM-based summarisation of events; the curator is purely deterministic projection.
  • Cross-repo memory-spine federation.

Open Questions

  • OQ1 — RESOLVED 2026-05-18: Stream lives repo-local at .biltiq/memory-stream.jsonl, gitignored. MEMORY.md (committed) is the cross-machine canonical projection; the per-machine stream is a regenerable buffer.
  • OQ2 — RESOLVED 2026-05-18: Both modes ship. On-demand curator invocation is the default path; an opt-in post-commit hook is provided but not installed by default (see AC8). Auto-trigger on session compaction remains out of scope (BILTIQ-017g-phase2).
