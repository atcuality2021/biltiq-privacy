Step 1 — Writer module + tests; delete stale lock M · ~45 min

Rationale: The writer is the smallest, most isolated unit. Atomic-append correctness is the load-bearing claim of the whole task — nail it first so every later step inherits a known-good event log. Deleting the stale .biltiq/curator.lock here keeps the cleanup adjacent to the file's first real use and out of the doc step's diff.

Files (CREATE): scripts/__init__.py, scripts/_memory_writer.py, conftest.py (repo root — prepends rootdir to sys.path because there is no root-level pyproject.toml yet), tests/scripts/conftest.py, tests/scripts/test_memory_writer.py.

Files (DELETE): .biltiq/curator.lock (stale zero-byte legacy from BILTIQ-000 onboarding; canonical path is dot-prefixed .biltiq/.curator.lock, created on first curator run).

Note: the original plan listed tests/scripts/__init__.py as a CREATE. Discovered during Build that the marker file caused pytest's prepend import mode to insert tests/ on sys.path, which collides with the real top-level scripts/ package (Python resolves import scripts to tests/scripts/ and scripts._memory_writer then 404s). Dropping the marker keeps test files rootless and lets the root-conftest sys.path insert work as designed. See Change History row 2.

Tests:
  • test_write_event_appends_one_valid_json_line — happy path (AC1).
  • test_write_event_concurrent_writers_no_interleave — 4 threads × 50 events → 200 valid lines, no garbled records (AC1).
  • test_write_event_required_fields_present — ts, event_type, payload, schema_version on every line (AC1).
  • test_write_event_rejects_oversize_payload — encoded line > PIPE_BUF raises MemoryEventTooLargeError (AC1).
  • test_write_event_rejects_empty_event_type and test_write_event_rejects_non_dict_payload — input validation (AC1).
  • test_write_event_unknown_type_accepted — arbitrary event types are written (curator-side filtering, not writer-side; AC4).
  • test_write_event_uses_BILTIQ_REPO_ROOT — conftest fixture redirection works (AC6a).

Gate: pytest tests/scripts/test_memory_writer.py -v — all GREEN. Verify .biltiq/curator.lock is gone via ls -la .biltiq/.

Files (CREATE): scripts/_memory_curator.py (skeleton: argparse, fcntl.flock acquire, stream read, atomic os.replace write of MEMORY.md unchanged, exit-code branches). Projection logic is a stub returning the file unchanged.

Rollback Plan

All changes are additive except (a) deletion of the stale zero-byte .biltiq/curator.lock in Step 1, and (b) the marker wrapping of existing MEMORY.md content in Step 4.

  • Steps 1–3 (writer + curator code + tests): revert the relevant commits. scripts/ disappears; tests/scripts/ disappears; the upstream biltiq-engineering plugin's call sites guard with try: … except ImportError: pass per the design's rollback note, so removing the module does not break standup or other commands — they simply stop persisting events again.
  • Step 4 (docs + markers): revert the commit. MEMORY.md returns to pre-marker state; the auto-curated blocks vanish; manual content is preserved by virtue of being plain text inside the marker wrapper. git show HEAD~1:MEMORY.md reproduces the byte-identical pre-marker version for diff verification.
  • Step 5 (hook): revert. If the dev already ran scripts/install-curator-hook.sh, the symlink at .git/hooks/post-commit will dangle — harmless (git silently skips broken hooks) but cosmetically untidy; running rm .git/hooks/post-commit cleans it up.
  • Stale lock cleanup (Step 1): non-reversible by revert (the file was zero bytes and stale; nothing to restore). Documented here for completeness.
  • The stream file (.biltiq/memory-stream.jsonl) is per-machine and gitignored. Rollback does not touch it. If desired, rm .biltiq/memory-stream.jsonl after rollback discards the local event log; no shared state is affected.

Data-loss assessment: none. No prod data, no schema, no migrations. MEMORY.md is the only committed file whose content is touched and its manual sections are guaranteed byte-equal across every step (verified by Step 3 tests and Step 4 gate).
