What Went Well

  • Parallel subagent review grouped by concern, not by line count. Four biltiq-code-reviewer subagents (Core Python / Shell / Tests / Docs) ran in parallel with slice-specific anti-pattern lenses. Slice 4 caught the AGENT_RULES.md:170 contract-drift that the inline correctness pass missed at Step 5. Pattern to repeat: dispatch subagents on conceptual axes, not file-count quotas.
  • Sandbox-isolated AC demonstrations via BILTIQ_REPO_ROOT. All four byte-level ACs (AC1 event shape, AC2 manual-preservation, AC3 lock contention, AC4 vocabulary) were demonstrated in mktemp -d sandboxes — proving exact JSON output without polluting the real repo. AC3 specifically used external flock -x to hold the lock while the curator tried to acquire, producing the byte-for-byte {"skipped": "another curator already running"} output the spec required.
  • Re-used existing POSIX-atomic JSONL convention. The writer's O_APPEND + single os.write() + PIPE_BUF cap pattern was lifted directly from the pre-existing .biltiq/estimates-history.jsonl shape. No new pattern invented — AP#1 (Duplication) closed via cross-reference, not via assumption.
  • verification-before-completion discipline held throughout. Every AC report quoted actual command output (md5sums, sha256s, exit codes, full JSON). Zero "I think it passes." claims. The Test step's full battery output was pasted verbatim into the PR body.

Process Changes Proposed

  • Review checklist should include a static-analysis pass. Test gate uncovered F401 + mypy object-hatch issues that Review's correctness pass missed because they're orthogonal concerns. Running ruff check + mypy --strict against the staged diff during Review would catch these one step earlier. Proposed change to biltiq-engineering:code-reviewer skill.
  • Contract-drift sweep: grep the whole document set, not just the most-visible site. Step 5's first fix updated AGENT_RULES.md:143 but left :170 and ADR-0001:10 stale. When fixing a wording claim that may exist in multiple documents (specs, ADRs, AGENT_RULES, MEMORY), require a repo-wide grep of the old wording before declaring the fix done. Proposed change to biltiq-engineering:build skill (which already has a similar rule for spec-renumber sweeps).
  • Upstream plugin schema gap — /biltiq-engineering:standup payload mismatch. Plugin emits {yesterday_summary, today_task, branch, blockers, trigger}; spec expected {date, did, doing, blockers}. Curator tolerates unknown keys (renders **Today (?):**) but the schemas should harmonise. Proposed: file an upstream issue against biltiq-engineering plugin to reconcile.
  • Repo lacks pyproject.toml. Default invocations of pytest / ruff at the repo root fail on test-scaffolds/python/example_test.py placeholder. Consider adding minimal config ([tool.pytest.ini_options] testpaths = ["tests"], [tool.ruff] extend-exclude = ["test-scaffolds"]) in a separate BILTIQ task.

Tech Debt Logged

Five items were filed at Ship time. A close-out audit on 2026-05-18 (chore PR following BILTIQ-001 + BILTIQ-003 merges) verdicts each item below. One closable (#4); four deferred-by-design or out-of-repo.

  • commit_metadata event type is reserved but has no in-repo producer. Listed in v1 vocabulary (spec AC4) and rendered into MEMORY.md's auto:code_areas section, but no path emits it. ADR-0001 line 10 documents this as an intentional reservation, not a defect. Decision deferred: either add a producer (e.g., a separate pre-commit hook that writes the event before the curator is triggered) or trim from v1 vocab if no producer materialises in the next sprint.
    Verdict (2026-05-18 close-out): DEFERRED-BY-DESIGN. Spec AC4 locks the vocabulary to include commit_metadata; adding a producer or trimming the vocab is a v2 spec decision, not a chore-PR fix.
  • Curator rebuilds auto-sections from full stream every run. Not incremental. Current perf budget passes at 6000× headroom (0.03s on a 1000-event stream against a 200ms target). Incremental projection is a deferred follow-up per ADR-0001 § "Tech debt accepted". Will become urgent if streams exceed ~10k events — not anticipated for solo-dev usage.
    Verdict (2026-05-18 close-out): DEFERRED-BY-DESIGN. ADR-0001 explicitly accepts this debt; perf budget has 6000× headroom. Will be re-opened when a real workload exceeds 10k events.
  • No stream archival/rotation policy. .biltiq/memory-stream.jsonl grows monotonically. Acceptable for solo-dev usage; multi-dev or long-horizon usage will need a rotation policy. Possibly a follow-up BILTIQ task once we have actual long-run data.
    Verdict (2026-05-18 close-out): DEFERRED. Premature without real long-run usage data; would design rotation against hypothetical access patterns. Re-evaluate after 90 days of multi-dev usage or first stream > 50 MB.
  • Repo lacks pyproject.toml. Tool scoping for pytest / ruff is ad-hoc — a future contributor running pytest at the repo root will hit a placeholder import in test-scaffolds/python/example_test.py. Out of scope for BILTIQ-003 (this is a BILTIQ-000 bootstrap omission).
    Verdict (2026-05-18 close-out): CLOSED in this chore PR. Root pyproject.toml was added by BILTIQ-001 (PR #1) but its [tool.pytest.ini_options].testpaths only listed the two package suites — tests/scripts/ (the BILTIQ-003 memory-spine tests) was missed. This PR appends tests/scripts so bare pytest from the repo root collects all three suites (34 tests + 1 skipped), and explicit testpaths keep test-scaffolds/ excluded as intended.
  • /biltiq-engineering:standup payload schema diverges from spec. Upstream fix needed in the biltiq-engineering plugin source, not in this repo. The curator's tolerance for unknown keys keeps things working but the harmonisation should land.
    Verdict (2026-05-18 close-out): OUT-OF-REPO. Fix lives in the engineering-plugin source tree; the curator's unknown-key tolerance keeps this repo functional in the meantime.
