Task ID
BILTIQ-010
Author
@atcuality2021
Created

Approach

Name

Pure free-function hash chain: two module-level functions (append_row, verify_chain) plus a documented genesis-hash constant in core/audit_chain.py, committing each row's hash to (prev_hash, canonical_json(payload)) via the already-shipped doc_hasher.hash_text. No class, no clock, no storage.

Description

CDSCO's backend/modules/audit.py hash-chains audit rows but binds the algorithm to an async SQLAlchemy session — only the ~50-LOC chaining core belongs in a leaf library (spec § Problem). This task ports only the commitment logic: each row carries an opaque caller-supplied payload plus a hash that cryptographically commits to the row before it (prev_hash) and the row's own content. Persistence stays entirely in the consumer (AC3) — the library returns rows; the consumer writes them wherever it likes.

Row schema. A row is a ChainedRow TypedDict with exactly three keys: prev_hash: str (the hash of the preceding row, or the genesis sentinel for the first row), payload: dict[str, JsonValue] (the caller-supplied event fields — any JSON-serialisable mapping, including a caller-supplied timestamp string per the resolved open question), and hash: str (the row's own commitment digest). The TypedDict is named ChainedRow — deliberately not AuditRecord, which is already taken by core/pseudonymiser.py for the per-span pseudonymisation row (a different concept: one replaced PII span, not one chained audit event). Reusing that name would be Anti-Pattern #1 (a parallel type under a colliding name).

Commitment recipe (the cross-language contract — AC4). Canonical serialization is fixed as json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=False) (resolved open question). The committed pre-image is the genesis-or-previous hash string concatenated directly with that canonical JSON, and the digest is taken by reusing doc_hasher.hash_text (AC1 reuse target — never a raw hashlib call):

canonical = json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
row_hash  = doc_hasher.hash_text(prev_hash + canonical)
#           = sha256((prev_hash + canonical).encode("utf-8")).hexdigest()

The pre-image ordering is prev_hash first, then canonical JSON. This is safe against the concatenation-ambiguity that plagues fixed-field schemes: prev_hash is always exactly 64 lowercase hex characters (a SHA-256 hex digest, or the genesis sentinel which is also 64 hex chars), so the boundary between the two segments is unambiguous by construction — the first 64 characters of the pre-image are the parent hash and everything after is the canonical payload. No delimiter is needed and none is used (a delimiter would itself become an injection surface). hash_text already utf-8-encodes its input, so the byte image is fully specified.

Genesis constant. The first row's prev_hash is a documented sentinel exported as GENESIS_PREV_HASH: Final[str] = "0" * 64 — 64 zero hex characters. Rationale: it is the same width and alphabet as a real SHA-256 hex digest (so the "prev_hash is always 64 hex chars" boundary invariant above holds for row 0 too, with no special-casing in the hashing path), it is the widely-recognised "null parent" convention from hash-chain practice, and the all-zero string is not itself a reachable SHA-256 output for any practical input, so it cannot be forged as a mid-chain link. It is a module-level Final constant, not a magic literal, so consumers and the native SDKs (011/012) bind to one documented value.

append_row. A pure function append_row(prev_hash, payload) -> ChainedRow: it computes the canonical JSON and the digest by the recipe above and returns the fully-populated ChainedRow. It does not mutate inputs, hold state, or read the clock — the caller passes GENESIS_PREV_HASH for the first row and the previous row's hash thereafter. To keep verification reproducible, payload must be canonical-JSON-serialisable; append_row validates this by performing the json.dumps (which raises the stdlib TypeError on a non-serialisable value) — that native exception is the rejection path, so no new library exception type is needed (see § Files to Touch).

verify_chain. A pure function verify_chain(rows) -> VerifyReport that walks the list once. For each row at index i it (a) recomputes the expected digest from the row's own stored prev_hash + canonical payload and checks it equals the stored hash (detects any mutation of payload or hash — AC2 tamper-evidence), and (b) checks the link: row 0's prev_hash must equal GENESIS_PREV_HASH, and every later row's prev_hash must equal the previous row's hash (detects reordering, insertion, deletion). The first index that fails either check is reported. The report is a VerifyReport TypedDict {valid: bool, first_broken_index: int | None}: {valid: True, first_broken_index: None} for an intact chain (including the empty chain — vacuously valid — and a single valid row), and {valid: False, first_broken_index: i} at the first break. verify_chain returns a report; it never raises on tamper (AC2) — tampering is a normal, reportable outcome, not an exceptional one.

Alternatives Considered

#AlternativeWhy Rejected
1Stateful AuditChain class holding the chain and a running prev_hash (the name stack.md currently reserves)Reserved name collides with intent and fights purity. A mutable chain object carries per-instance state that defeats the deterministic, side-effect-free contract AC3/AC4 demand, complicates the cross-language reproduction the native SDKs need, and reintroduces the kind of hidden state the library elsewhere avoids. The reserved stack.md row is rewritten to the free-function API (see § Files to Touch).
2Fixed-field string concatenation of the pre-image (e.g. prev_hash + "|" + entity + "|" + ts) instead of canonical JSONDelimiter-injection (a payload value containing the delimiter shifts field boundaries and lets two distinct payloads collide on one pre-image) plus field-order fragility (any caller or language ordering fields differently produces a different digest, breaking cross-machine verification — AC4). Canonical JSON with sort_keys=True fixes key order once for all languages.
3Library-generated timestamp (call datetime.now(timezone.utc) inside append_row)Breaks purity/determinism (AC3, AC4): identical inputs would produce different hashes across calls, so chains could not be reproduced or verified offline. The resolved open question fixes timestamps as a caller-supplied ordinary payload field; the module imports no clock. (Consumers needing one still use datetime.now(timezone.utc) per approved-versions.md — outside this module.)
4@dataclass(slots=True, frozen=True) row type (the stack.md default for return values)The chain must round-trip through arbitrary consumer storage (JSON files, Postgres rows) and across the native SDKs, where the natural wire shape is a plain JSON object. A TypedDict is a runtime dict — it serialises and re-loads with no conversion and mirrors the shipped Detection/AuditRecord TypedDict precedent in this package, whereas a frozen dataclass would force a serialise/deserialise shim at every persistence boundary.
5HMAC-keyed chain (MAC each row with the BILTIQ-007 HMAC key) instead of a plain hashOut of scope per spec § Out of Scope (asymmetric/keyed signing is a follow-up if a consumer needs non-repudiation). A keyed MAC would thread a secret into a module that is deliberately key-free and stateless, and a plain hash already satisfies the tamper-evidence contract (AC2) for the integrity use case. Flagged as an explicit non-goal in § Security & Compliance.
6Embed prev_hash inside payload and hash only the payloadConflates two roles in one field (caller-owned event data vs. the chain link the library owns) and makes it ambiguous whether prev_hash is auditable content or chain plumbing. Keeping prev_hash a top-level row field, committed via the pre-image prefix, keeps the payload purely the consumer's event and the link purely the library's.

Data Model Changes

Two new in-module TypedDicts and one module constant; no DB table, no JSONL field, no schema migration. JsonValue is the recursive JSON type alias keeping payload typed without Any (Anti-Pattern #4).

# core/audit_chain.py
from __future__ import annotations
from typing import Final, TypeAlias, TypedDict

# Recursive JSON value alias — keeps payload fully typed, no Any.
# TypeAlias form (not the PEP 695 `type X = ...` statement) so the module
# imports cleanly on the supported floor, Python 3.11 (requires-python >=3.11);
# the `type` statement is 3.12+ grammar. The `|` union operator and the
# "JsonValue" string forward-refs are both 3.11-safe at runtime.
JsonValue: TypeAlias = (
    str | int | float | bool | None
    | list["JsonValue"] | dict[str, "JsonValue"]
)

GENESIS_PREV_HASH: Final[str] = "0" * 64   # 64 zero hex chars = null parent

class ChainedRow(TypedDict):
    prev_hash: str                  # parent row's hash, or GENESIS_PREV_HASH for row 0
    payload: dict[str, JsonValue]   # caller-supplied event fields (incl. any timestamp)
    hash: str                       # sha256(prev_hash + canonical_json(payload))

class VerifyReport(TypedDict):
    valid: bool
    first_broken_index: int | None  # None when valid; else the first failing row index

The committed payload is an opaque caller-owned mapping. The library does not inspect, require, or generate any field — including timestamp, which is an ordinary caller-supplied payload key (resolved open question). ChainedRow is a runtime dict, so a chain is a plain list[ChainedRow] that JSON-serialises for storage and re-loads for verify_chain with no conversion. The shipped BILTIQ-007 AuditRecord/Detection types are untouched.

API Contract Changes

New public surface under biltiq_privacy.core.audit_chain, re-exported from biltiq_privacy.core. No existing contract changes. All signatures fully typed; no Any, no type: ignore; mypy --strict clean.

# core/audit_chain.py  — public surface

GENESIS_PREV_HASH: Final[str]   # "0" * 64

class ChainedRow(TypedDict):    # {prev_hash, payload, hash}  (see Data Model)
    ...
class VerifyReport(TypedDict):  # {valid, first_broken_index}
    ...

def append_row(prev_hash: str, payload: dict[str, JsonValue]) -> ChainedRow:
    """Compute and return the next chained row.

    hash = hash_text(prev_hash + json.dumps(payload, sort_keys=True,
                     separators=(",", ":"), ensure_ascii=False)).
    Pass GENESIS_PREV_HASH as prev_hash for the first row. Pure: no
    state, no clock, no I/O. Raises TypeError (stdlib, from json.dumps)
    if payload is not JSON-serialisable.
    """

def verify_chain(rows: list[ChainedRow]) -> VerifyReport:
    """Recompute each row's hash and validate the prev_hash links.

    Returns {valid: True, first_broken_index: None} for an intact chain
    (empty chain is vacuously valid); {valid: False, first_broken_index: i}
    at the first row whose recomputed hash mismatches its stored hash OR
    whose prev_hash != the prior row's hash (row 0 must equal
    GENESIS_PREV_HASH). Never raises on tamper.
    """
  • Commitment seam: the pre-image is prev_hash + canonical_json(payload), digested through doc_hasher.hash_text (so the SHA-256 + utf-8 encoding is shared with the rest of the engine, not re-implemented). The 64-hex-char prev_hash prefix makes the segment boundary unambiguous with no delimiter.
  • Determinism: identical (prev_hash, payload) always yields an identical row; sort_keys=True makes payload key insertion-order irrelevant (AC4).
  • No clock, no env, no config, no network, no storage (AC3).

Security & Compliance

  • Compliance mode on_prem_preferred: the module is pure stdlib json + the in-repo doc_hasher. No external/cloud AI, no network, no LLM, no new dependency → no ADR required for a dependency.
  • Cross-language contract ADR (recommended): the canonical-serialization + pre-image recipe is a byte-exact contract that BILTIQ-011, BILTIQ-012, and the native Node/PHP/Go SDKs must reproduce identically to verify chains across languages. A lightweight ADR (next free number ADR-0005 in docs/adr/ — 0001–0004 are taken) documenting the recipe (canonical JSON params, prev_hash-first pre-image ordering, "0"*64 genesis) plus a committed golden test vector is recommended so the SDK ports bind to a written spec, not to a reading of the Python source. This ADR documents a serialization decision, not a new dependency.
  • AC3 framework-free gate: no SQLAlchemy / DB / session / FastAPI / LLM / cloud import — the library-framework auto-block in code review is satisfied structurally.
  • No PII handling by the library: payload is opaque and caller-owned; the library neither inspects nor logs it (the module has no logging call and no print()). Whether a payload contains PII is the consumer's concern. Tests use synthetic data only (DPDP 2023 §4) — no real identifiers in any fixture or golden vector.
  • Non-goal — keyed signing: this is a plain hash chain (integrity / tamper-evidence), not a MAC and not an asymmetric signature, so it gives no non-repudiation against a party who can rewrite the whole chain. That is explicitly out of scope (spec § Out of Scope) and noted here as a future asymmetric-signing follow-up if a consumer needs it.

Performance Considerations

append_row is one json.dumps + one SHA-256 over a small string — constant work per row, no hot path of concern. verify_chain is a single O(n) pass over the chain, recomputing exactly one hash per row and comparing two strings; no nested scan, no re-hash of earlier rows. Memory is O(1) beyond the input list (the walk keeps only the previous row's hash). For any realistic audit volume the cost is dominated by the consumer's storage I/O, which lives outside this module. No latency-budget concern.

Risks

RiskSeverityMitigation
Canonical-JSON byte-reproduction across languages — Node JSON.stringify, PHP json_encode, and Go encoding/json differ from Python's json.dumps on float formatting, non-ASCII escaping, integer vs. float, and key sorting. A divergent byte image breaks cross-language verification (AC4). MED Pin the exact Python params (sort_keys=True, separators=(",", ":"), ensure_ascii=False) as the authoritative recipe in ADR-0005, and commit a golden test vector (a fixed payload → fixed row hash) the Python test asserts now and each native SDK must reproduce when it lands. Document the float/int caveat in the ADR so SDK ports constrain payloads to JSON-safe primitive shapes.
Empty-chain and single-row edge cases — an off-by-one in the link walk could make an empty chain raise (instead of returning valid=True) or skip the genesis check on the lone row. LOW AC5 mandates explicit empty-chain and single-row tests; the design fixes empty → {valid: True, first_broken_index: None} (vacuous) and row 0's prev_hash must equal GENESIS_PREV_HASH. Both pinned by Step-2 tests including a single-row-with-bad-genesis negative case.
hash_text input-encoding assumption — the commitment relies on hash_text utf-8-encoding its input; if that ever changed, every chain hash would shift. LOW hash_text is the shipped BILTIQ-007 primitive with a fixed utf-8 contract and its own golden-digest tests; reusing it (rather than a raw hashlib call) keeps the encoding single-sourced. The golden-vector test in Step 2 fails loudly if the digest path ever drifts.
prev_hash boundary assumption — the delimiter-free pre-image relies on prev_hash always being exactly 64 hex chars. A caller passing a malformed prev_hash to append_row would still hash, but verify_chain would later reject the link. LOW The genesis sentinel and every produced hash are 64 hex chars by construction, so correct usage never violates the invariant. verify_chain's link check catches any malformed prev_hash as a break at that index, so a misuse is reported, not silently accepted. (Strict format validation in append_row is deferred — flagged for the dev; see report.)

Coordination: audit_chain.py is a fresh file; no in-flight task touches it. MEMORY.md's active work is BILTIQ-006 (memory-spine, in scripts/) — disjoint. The core/__init__.py and stack.md edits are additive (new re-exports; rewrite of a placeholder row), not changes to shipped behaviour. The ChainedRow/VerifyReport surface is the contract BILTIQ-011 (verify) and BILTIQ-012 (emit-per-call) will consume; this design freezes it.
