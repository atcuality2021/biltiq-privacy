What Went Well

  • The design.html "alternatives considered" table killed fixed-field concatenation before it cost anything. Canonical JSON was chosen with delimiter-injection and field-order fragility named as the explicit rejection reasons; that reasoning landed verbatim in ADR-0005, so the cross-language contract is defensible rather than assumed.
  • Caller-supplied timestamp (no clock read) made the golden vector reproducible offline. Because append_row never calls datetime.now(), the same payload always commits to the same digest — which is exactly what let test_golden_vector_pins_cross_language_recipe pin b94c22ac…855b65 as the conformance anchor for the future Node/PHP/Go SDKs. Purity was not an aesthetic choice; it was the precondition for cross-language verifiability (AC3 → AC4).
  • AP#1 (Duplication) defended at design and confirmed mechanically. The row type was named ChainedRow to avoid colliding with pseudonymiser.AuditRecord, and the hash reuses BILTIQ-007's doc_hasher.hash_text rather than opening a second hashlib.sha256 call site. A range-wide grep for duplicate append_row/verify_chain/_canonical_json/ChainedRow/VerifyReport definitions returned none.
  • Independently recomputing the ADR-0005 golden vector against the live implementation before shipping. Since the ADR is the cross-language contract, a wrong digest there would propagate to every SDK. Both the canonical string and the hex digest were recomputed from _canonical_json + append_row and matched the documented values — the doc and the code cannot silently diverge.
  • Fixed 64-hex-char prev_hash width removed the need for a delimiter byte. The pre-image prev_hash + canonical is unambiguous because the parent link is always exactly 64 chars — one fewer thing every cross-language re-implementation must match. Documented in the module docstring and ADR-0005 alternative #4.
