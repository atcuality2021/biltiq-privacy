Step 4 — detectors/presidio_backend.py: PresidioDetectorM

Rationale: The port itself — CDSCO's detect_pii_rules() behaviour behind the ABC, reusing 002. Depends on Steps 1–3. Est. ~45 min.

Files: CREATE packages/python-core/biltiq_privacy/detectors/presidio_backend.py — SPDX + CDSCO-origin docstring; class PresidioDetector(Detector) with __init__(self, *, score_threshold: float = 0.5) storing self._score_threshold + self._engine: AnalyzerEngine | None = None; detect() lazily builds self._engine = build_engine() on first call (instance-level singleton, AC3), calls engine.analyze(text=text, language=language), projects each result to {entity_type, start, end, score: round(r.score, 4), text: text[r.start:r.end], source: "presidio"}, filters score >= self._score_threshold (AC4). The presidio_analyzer + build_engine imports are method-level (AC5). The lazy-build call is wrapped to catch OSError specifically → raise MissingNERModelError(...) from err (AC3, Anti-Pattern #3 — no bare except). CREATE packages/python-core/tests/detectors/test_presidio_backend.py (cases below).

Tests (AC2, AC3, AC4, AC6 — use the Step-3 fixtures):
  • test_detects_each_indian_entity — PresidioDetector().detect(sample_indian_pii) returns at least one record per expected IN_* entity type present in the sample (AC6 success path); each record has exactly the 6 keys with source == "presidio".
  • test_score_is_rounded_4dp — every returned score equals round(score, 4) (characterization fidelity to CDSCO).
  • test_default_threshold_keeps_high_confidence — default 0.5 retains the high-score entities (Aadhaar @0.95, PAN/GSTIN/Phone @0.9) (AC4 success path).
  • test_raised_threshold_drops_low_confidence — PresidioDetector(score_threshold=0.8) drops the low-score hits (Voter ID @0.7, Medical Reg @0.6) while keeping the high-score ones (AC4 boundary path).
  • test_engine_is_lazy_singleton — self._engine is None before the first detect(); two detect() calls reuse the same engine object (AC3 — no rebuild, no module global).
  • test_missing_ner_model_maps_to_error — monkeypatch the backend's build_engine to raise OSError; detect() raises MissingNERModelError with the install-guidance string and chains the original via __cause__ (AC3 failure path). A non-OSError (e.g. ValueError) from build_engine propagates unwrapped (proves the catch is scoped, not bare).
  • test_empty_text_returns_empty_list — detect("") returns [] (guard path).
