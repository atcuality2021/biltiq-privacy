Task ID
BILTIQ-009
Author
@atcuality2021
Created

Approach

Name

Decouple-don't-rewrite: a stateless Detector ABC in detectors/base.py plus a PresidioDetector in detectors/presidio_backend.py that wraps the already-shipped BILTIQ-002 indian.recognisers.build_engine() behind an instance-level lazy singleton.

Description

CDSCO's presidio_engine.py bundles three things into one file: the eight Indian recognisers, a module-global _engine singleton, and the detect_pii_rules() wrapper that calls engine.analyze() and projects results into {entity_type, start, end, score, text, source} dicts filtered at score >= 0.5. BILTIQ-002 already owns the recognisers (as INDIAN_RECOGNISERS + the pure build_engine() factory). This task ports only the wrapper behaviour, and does so behind an abstraction so future backends (LLM/hybrid, Phase D) plug in without touching the core pipeline.

The seam is exactly the line CDSCO already exposes: PresidioDetector.detect() builds its engine once via build_engine() (reused verbatim — AC2, no recogniser re-definition), caches it on self._engine (instance-level lazy singleton, AC3 — not a module global; preserves 002's deliberate pure-factory design), calls engine.analyze(text=text, language=language), and projects each RecognizerResult into a DetectedEntity record with round(score, 4) (verbatim from CDSCO) filtered at the configurable self._score_threshold (default 0.5, AC4). The return type is DetectedEntity(Detection) — a one-field subclass of the shipped BILTIQ-007 Detection TypedDict adding only source: str, defined in detectors/base.py. A TypedDict is a plain dict at runtime, so AC1's list[dict] contract holds literally and the dict-consuming 011/012 callers are unaffected; subclassing Detection avoids Anti-Pattern #1 (no parallel type).

AC5 (framework-free + lazy import) is enforced structurally: both modules carry no FastAPI/DB/LLM imports, and the from presidio_analyzer import ... / from biltiq_privacy.indian.recognisers import build_engine statements live inside methods, not at module top — so importing detectors.base or detectors.presidio_backend does not transitively pull Presidio or spaCy into sys.modules. This mirrors BILTIQ-002's lazy-import discipline and is proven the same way: a subprocess import-probe test (the existing tests/indian/test_lazy_import.py harness is the template). A missing en_core_web_sm surfaces during lazy engine build as an OSError, which the backend catches specifically (never bare Exception, Anti-Pattern #3) and re-raises as the new MissingNERModelError (added to core/exceptions.py beside HMACKeyRequiredError, as overview.md § Failure modes reserves) with python -m spacy download en_core_web_sm install guidance.

Alternatives Considered

#AlternativeWhy Rejected
1Port the CDSCO module verbatim, including its eight inline PatternRecognizers and _build_engine()Anti-Pattern #1 — BILTIQ-002 already ships those recognisers + build_engine(); re-defining them creates a divergent parallel copy (the CDSCO regexes lack the 002 context-word boosts and single-source patterns). AC2 mandates reuse.
2Module-global _engine singleton + module-level get_engine() (CDSCO shape)Reintroduces the process-global state BILTIQ-002 deliberately removed (its build_engine() is a pure factory). A module global cannot be reset/garbage-collected per-consumer and complicates multi-detector use. Instance-level self._engine (resolved open question) keeps the singleton scoped to the detector.
3@dataclass(slots=True, frozen=True) return type (the stack.md default for return values)Breaks the dict-consuming contract — CDSCO and BILTIQ-011/012 read r["entity_type"]; a frozen dataclass needs attribute access and would force a parallel shape next to the shipped Detection TypedDict (Anti-Pattern #1). The resolved open question fixes the return type as DetectedEntity(Detection). (Dataclass remains the default for genuinely new return values; here a typed dict already exists to extend.)
4Bare list[dict] with no element type (CDSCO verbatim)dict with no value type trips mypy --strict and the no-Any rule (Anti-Pattern #4 — silent type erosion). DetectedEntity documents the six keys while staying a runtime dict.
5Eager engine build in __init__Breaks AC5 lazy-import (constructing a PresidioDetector would load spaCy + the ~2–4 s model even if detect() is never called) and slows every import path that merely references the class. Lazy self._engine on first detect() is required.
6Catch bare Exception (or Exception + isinstance sniff) around engine build to map model-missing errorsAnti-Pattern #3 — masks unrelated failures (registry errors, config bugs) as "model missing". spaCy raises OSError specifically when the model package is absent; catch exactly that and let everything else propagate.
7Wire build_engine() at module import and inject the engine via PresidioDetector(engine=...)Forces the caller to construct the engine (re-leaking the spaCy import to import-time at the call site) and removes the lazy/singleton guarantee the backend owns. The optional nlp_engine seam already exists on build_engine() for advanced wiring; the detector does not need to expose it in v0.1.0.

Data Model Changes

One new in-module type and one ABC; no schema, no JSONL field, no DB table.

# detectors/base.py
from biltiq_privacy.core.pseudonymiser import Detection

class DetectedEntity(Detection):   # Detection = {entity_type, text, start, end, score}
    source: str                    # adds the single extra key; runtime dict

class Detector(abc.ABC):
    @abc.abstractmethod
    def detect(self, text: str, language: str = "en") -> list[DetectedEntity]: ...

DetectedEntity is a structural superset of Detection, so a list[DetectedEntity] is accepted by Pseudonymiser.pseudonymise_text (which consumes list[Detection]) without conversion. No edits to the shipped BILTIQ-007 Detection / AuditRecord types — they remain frozen.

API Contract Changes

New public surface under biltiq_privacy.detectors (re-exported from the package __init__). No existing contract changes — both modules are new and the 007 types are untouched. All signatures fully typed; no Any, no type: ignore.

# detectors/presidio_backend.py
class PresidioDetector(Detector):
    def __init__(self, *, score_threshold: float = 0.5) -> None: ...
    def detect(self, text: str, language: str = "en") -> list[DetectedEntity]: ...
  • Engine reuse seam: detect() lazily builds and caches self._engine = build_engine() (BILTIQ-002 factory) on first call; subsequent calls reuse it. No nlp_engine arg is surfaced on the detector in v0.1.0 (advanced NLP wiring stays on build_engine() directly).
  • detect() behaviour: calls engine.analyze(text=text, language=language), projects each result to {entity_type, start, end, score: round(score, 4), text, source: "presidio"}, filters score >= self._score_threshold. Order follows Presidio's result order (CDSCO-equivalent; not sorted).
  • Errors: a missing NER model raises MissingNERModelError (with install guidance) on the first detect(); no other exception is wrapped.

No new environment variables. No CLI change. No network, no config read.

Security & Compliance

  • Compliance mode on_prem_preferred: detection is in-process Presidio + local spaCy — no external/cloud AI call, no network, no LLM. No new dependency introduced (Presidio/spaCy are already approved & pinned) → no ADR required.
  • AC5 framework-free gate: no FastAPI/Starlette/Pydantic/DB/LLM import in either module; the auto-block in code review for library framework deps is satisfied. The lazy method-level import keeps Presidio/spaCy out of import time, proven by the subprocess probe test.
  • No key, no secret, no env read inside python-core. The detector holds only a float threshold and the cached engine.
  • No PII logged: neither module has a logging call or print(); detected span text is returned to the caller, never emitted to a log or stdout.

Performance Considerations

Cold start: the first detect() on a fresh PresidioDetector builds the engine and loads en_core_web_sm — ~2–4 s, once per instance (overview.md latency budget, line 107). The instance-level singleton means that cost is paid once per detector, not per call. Warm path: ~10–40 ms per kilobyte of text (overview.md line 105 — Presidio + spaCy NER). The DetectedEntity projection is an O(n) comprehension over results — negligible relative to analyze(). detect() is the hot path; no extra allocation or re-scan is introduced over CDSCO's wrapper. Threshold filtering is a single comparison per result.

Risks

RiskSeverityMitigation
Lazy-import regression — a top-level from presidio_analyzer import ... (or an eager re-export in detectors/__init__.py that pulls presidio_backend's imports to import-time) silently breaks AC5. MED Method-level imports only; the Step 5 subprocess probe asserts detectors.base, detectors.presidio_backend, AND detectors (the package) load neither presidio nor spaCy, with a positive control. Re-run after the Step 6 re-export edit. Keep the presidio_backend symbol re-export lazy-safe (the class body's method-level imports must not be hoisted).
OSError catch scope — too broad swallows unrelated I/O faults as "model missing"; too narrow misses the real spaCy "model not found" surface (spaCy may wrap the missing-package error and the exact type / message can shift across spaCy 3.7–3.8). MED Catch OSError specifically around the engine-build call (never bare Exception, Anti-Pattern #3), re-raise MissingNERModelError with from err to preserve the chain, and let any non-OSError propagate. A test monkeypatches build_engine to raise OSError and asserts the mapping + guidance string; Build confirms the live spaCy missing-model error is an OSError subclass against the pinned spacy >= 3.7, < 4.
Fixture drift — stack.md documents presidio_engine_indian / sample_indian_pii but they don't exist, and the line-95 wording says "7 Indian recognisers" when the set is 8. LOW This task creates both fixtures (closing the drift) and corrects the 7→8 wording in the same PR (stack.md edit row). The sample_indian_pii fixture is built from the existing synthetic *_VALID tuples — no new PII.
Threshold default mismatch — diverging from CDSCO's 0.5 would change which low-confidence hits (e.g. Medical Reg @0.6, Voter ID @0.7) survive. LOW Default fixed at score_threshold = 0.5 (AC4, matches CDSCO). A characterization test pins both the default (0.5 keeps the entity hits) and a raised threshold (e.g. 0.8 drops Voter ID @0.7 / Medical Reg @0.6).
Presidio version skew — a future analyze() / RecognizerResult API change (the pin allows >= 2.2, < 3) could alter result fields or scoring. LOW Pin already tight (< 3); the projection reads only the stable entity_type/start/end/score fields. Major-version bumps require an ADR + golden-corpus run per approved-versions.md line 114.

Coordination: the two detectors/ modules are fresh files; no in-flight task touches them. BILTIQ-006 (per MEMORY.md) is in scripts/ memory-spine, disjoint. The conftest + tests/fixtures/ edits are additive (new fixtures, no change to hmac_key or the existing collection plumbing). DetectedEntity and the Detector ABC are the contract BILTIQ-012 will consume; this design freezes that surface.
