Problem

The pipeline needs a pluggable detection abstraction so backends (rule-based Presidio now; LLM/hybrid later) are swappable. BILTIQ-002 already ported the 8 Indian recognisers + build_engine() into indian/recognisers.py. CDSCO's presidio_engine.py wraps Presidio + those recognisers behind a detect_pii_rules(text) -> list[dict] call. This task defines a Detector ABC and a PresidioDetector that reuses the existing 002 engine — it must not re-implement the recognisers.

User Impact

Internal/infra. Gives the engine a stable detection interface the orchestrator (BILTIQ-012) depends on, and the seam where Phase D's LLM/hybrid backends plug in without touching the core pipeline.

Acceptance Criteria

  • OPENAC1 — detectors/base.py defines a Detector ABC with detect(text: str, language: str = "en") -> list[dict] returning {entity_type, start, end, score, text, source} records.
  • OPENAC2 — detectors/presidio_backend.py implements the ABC over the existing indian.recognisers.build_engine(); it imports and reuses 002, and does not redefine any recogniser/pattern.
  • OPENAC3 — spaCy/Presidio init is lazy + singleton; a missing NER model raises MissingNERModelError with install guidance (per overview.md).
  • OPENAC4 — Confidence threshold is configurable (default 0.5, matching CDSCO).
  • OPENAC5 — No FastAPI/DB/LLM imports in either module; lazy-import gate keeps Presidio out of import-time for callers that don't detect.
  • OPENAC6 — Tests: backend detects each of the 8 Indian entity types on sample text; threshold filtering verified.

Out of Scope

  • LLM/contextual backend and hybrid ensemble (BILTIQ-020, needs ADR).
  • EU/US/UK recogniser packs (Phase C).
  • New recogniser definitions — reuse 002 only.

Open Questions

  • RESOLVED (2026-06-01): Return type — subclass the shipped BILTIQ-007 Detection TypedDict: class DetectedEntity(Detection): source: str. Detection is {entity_type, text, start, end, score}; the detector record adds only source. A TypedDict is a plain dict at runtime, so AC1's list[dict] contract holds literally, CDSCO + 011/012 dict consumers are unaffected, and the pseudonymiser (which consumes Detection) accepts it structurally. Avoids Anti-Pattern #1 (no parallel type).
  • RESOLVED (2026-06-01): Singleton placement — instance-level lazy self._engine on PresidioDetector, NOT a module global. Preserves BILTIQ-002's deliberate no-global-singleton design (build_engine() stays a pure factory); CDSCO's module-level _engine is not ported. v0.1.0 assumes single-threaded construction — no init lock (revisit if the sidecar shares one detector across threads).
  • RESOLVED (2026-06-01): MissingNERModelError trigger — catch the OSError spaCy raises when en_core_web_sm is absent during lazy engine init, and re-raise as MissingNERModelError (added to core/exceptions.py beside HMACKeyRequiredError, as overview.md § Failure modes reserves) with python -m spacy download en_core_web_sm install guidance. Catch OSError specifically, not bare Exception (Anti-Pattern #3).
  • RESOLVED (2026-06-01): Test fixtures — add the presidio_engine_indian and sample_indian_pii fixtures that stack.md already documents but which do not yet exist (only hmac_key is in conftest), closing the stack.md drift.
  • RESOLVED (2026-06-01): Score rounding — preserve CDSCO's round(score, 4) in the output record verbatim (characterization fidelity).
