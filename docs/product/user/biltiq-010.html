BILTIQ-010 — User Guide

Feature: Audit Hash-Chain (Pure Implementation)

Audience: Infrastructure & Backend Developers

What This Does

The biltiq_privacy.core.audit_chain module provides a lightweight, stateless, and tamper-evident mechanism for creating audit logs. Unlike traditional audit systems, this module is purely algorithmic: it handles the cryptographic commitment of data without imposing a database, web framework, or specific storage engine.

Key Capabilities

  • Tamper-Evidence: Uses SHA-256 hash-chaining to ensure that any modification, insertion, deletion, or reordering of rows is cryptographically detectable.
  • Deterministic Serialization: Implements a strict "Canonical JSON" contract (sort-keys, compact separators, UTF-8) to ensure chains are byte-identical across different programming languages and operating systems.
  • Zero Side-Effects: The library does not read the system clock or write to disk. It is a functional tool that expects the caller to provide timestamps and handle persistence.
  • Regulatory Alignment: Designed with the spirit of 21 CFR Part 11 and Annex 11 in mind, providing a portable, verifiable audit trail.

Getting Started

To begin using the audit chain, you will primarily interact with the GENESIS_PREV_HASH constant and the append_row function.

Core Concepts

  • Genesis: The very first row in a chain must use the constant GENESIS_PREV_HASH (64 zero characters) as its prev_hash.
  • ChainedRow: A dictionary containing prev_hash, a payload (your data), and the resulting hash.

Basic Implementation Pattern

from biltiq_privacy.core.audit_chain import (
    append_row, verify_chain, GENESIS_PREV_HASH
)

# 1. Create the first row (Genesis)
row0 = append_row(GENESIS_PREV_HASH, {"event": "system_start", "ts": "2026-06-01T00:00:00Z"})

# 2. Create subsequent rows using the previous hash
row1 = append_row(row0["hash"], {"event": "user_login", "user": "admin"})

# 3. Form a chain
audit_log = [row0, row1]

# 4. Verify integrity
report = verify_chain(audit_log)
print(f"Is valid: {report['valid']}")

Common Tasks

Generating a New Audit Trail

When starting a new sequence, always anchor your first call to append_row with GENESIS_PREV_HASH. All subsequent rows must use the hash value of the row immediately preceding it.

Verifying an Existing Chain

The verify_chain(rows) function performs a single forward walk through the provided list. It detects:

  • Payload Mutation: If a single byte in the payload changes.
  • Hash Corruption: If the stored hash itself is altered.
  • Reordering/Insertion/Deletion: If the sequence of hashes is broken.

If a failure is found, the function returns valid: False along with the first_broken_index.

Handling Timestamps

Important: This library never calls the system clock. To ensure the chain is deterministic and reproducible, you must include the timestamp inside your payload dictionary.

Troubleshooting

Symptom Probable Cause Resolution
TypeError during append_row Payload contains non-JSON serializable data (e.g., a Python set or custom object). Ensure all payload values are standard JSON types (str, int, float, bool, dict, list, None).
verify_chain returns valid: False The data has been tampered with or the sequence is interrupted. Check the first_broken_index to identify exactly where the integrity break occurred.
Chains fail to verify across different machines Non-canonical JSON serialization is being used by the consumer. Ensure you are using the append_row function provided by this library, which enforces canonical key ordering and spacing.
