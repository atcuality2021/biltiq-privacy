BILTIQ-010 — Developer Guide

Feature: Audit Hash-Chain (Pure Implementation)

Audience: Developer

Overview

BILTIQ-010 provides a pure, stateless, and tamper-evident audit hash-chain within the biltiq_privacy.core.audit_chain module. Unlike previous iterations coupled to SQLAlchemy and async database sessions, this implementation is a "leaf library" function. It focuses solely on the cryptographic commitment of data, leaving persistence (Postgres, S3, JSON files) entirely to the consumer.

Compliance Spirit: Designed to meet 21 CFR Part 11 and Annex 11 requirements for data integrity through cryptographic chaining.
  • Deterministic: Uses canonical JSON serialization to ensure cross-machine/language consistency.
  • Stateless: No side effects, no database drivers, and no clock reads.
  • Tamper-Evident: Detects payload mutation, hash corruption, reordering, insertion, and deletion.

Architecture and APIs

The module relies on two primary functions and one global constant. All functions are pure and deterministic.

Core Constants

GENESIS_PREV_HASH: str = "0" * 64  # 64 zero hex characters

Used as the prev_hash for the very first row in a chain.

Data Structures

ChainedRow (TypedDict):

{
    "prev_hash": str,    # Hash of preceding row or GENESIS_PREV_HASH
    "payload": dict,     # Caller-supplied JSON-serializable data
    "hash": str          # SHA-256(prev_hash + canonical_json(payload))
}

Functions

append_row(prev_hash, payload) -> ChainedRow

Computes a new row given the previous hash and a payload. It uses doc_hasher.hash_text for the digest.

verify_chain(rows) -> VerifyReport

A single-pass forward walk that validates both the individual row hashes and the link integrity between rows.

# Example VerifyReport
{
    "valid": bool,
    "first_broken_index": int | None
}

Integration and Extension

Canonical Serialization (ADR-0005)

To ensure the chain can be verified across different programming languages, the following serialization contract is enforced:

json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=False)

Persistence Strategy

The library does not perform I/O. Integration follows this pattern:

  1. Fetch last_hash from your database.
  2. Call append_row(last_hash, new_event).
  3. Persist the resulting ChainedRow to your storage medium.

Timestamps

To maintain purity and determinism, the library never reads the system clock. Consumers must include a timestamp as a field within the payload.

Testing and Local Run

The implementation includes rigorous test suites covering the following scenarios:

  • Happy Path: Building a multi-row chain and verifying it returns valid: True.
  • Tamper Detection: Mutating a single character in a payload or a hash and verifying the first_broken_index is correctly identified.
  • Structural Integrity: Reordering rows or deleting a middle row to ensure the link check fails.
  • Edge Cases: Verifying empty chains (vacuously valid) and single-row chains (linked to Genesis).

Run tests via:

pytest packages/python-core/tests/test_audit_chain.py
